## 조건
dev 앞 10건(gs-001~010), 캐시 없이 운영 구성 전체를 1회씩 호출. Extractor Sonnet 5.5(B1, v4, effort medium), Sentinel·Verifier·Re-listener는 Haiku 5.5(effort low). 단가 기준일 2026-10-26. 승인 $0.55, **실제 총 $0.1287**. 이 Windows PC의 네트워크에서 한 번 실행했다.

## 결과 (방문당 평균, 구성은 누적)
| 구성 | 호출/건 | 비용/건 | 지연 순차 | 지연 병렬 |
|---|---|---|---|---|
| Extractor | 1.0 | $0.0121 | 3.68초 | 3.68초 |
| + Sentinel LLM 보조 | 2.0 | $0.0123 | 4.85초 | 3.68초 |

- **순차**: 호출별 지연의 합. **병렬**: Extractor‖Sentinel, 이어서 위험 필드 전체의 Verifier‖Re-listener를 스레드로 실제 실행한 벽시계. "+ Verifier" 병렬값은 실측이 아니라 "1단계 + 가장 느린 Verifier 호출"로 추정했다. 같은 모델로 전체 구성을 추정하면 5.07초로 실측 5.08초와 맞는다.
- 호출별 지연: Extractor 평균 3.68초(p95 5.76), Sentinel 1.17초, Verifier 1.38초(p95 2.35), Re-listener 1.51초(p95 2.13).
- 위험 필드는 방문당 평균 2.3개(10건 중 3건은 0개)라 호출 수는 설계 추정(5~11회)의 아래쪽인 6.6회다.

## 읽는 법
1. **비용은 Extractor가 지배한다**(방문당 94%). Verifier+Re-listener+Sentinel을 모두 켜도 +$0.0008(+7%). 이득이 입증되지 않은 상태에서도 비용 부담은 작다.
2. **지연이 진짜 비용이다.** 순차로 돌리면 검증 단계가 +6.7초지만 병렬이면 +1.4초(총 5.1초). 병렬 실행이 이 구성의 전제다.
3. **병렬화 전 `/drafts` API는 순차였다**(예상 약 8초, 미실측). 같은 날 병렬화해 운영 코드 경로를 실측했다: 평균 4.87초(아래 "운영 코드 경로 실측").
4. 발표의 "방문당 비용 약 1.3센트, 지연 약 5초(병렬)"는 아래 한계 안에서만 말한다.

# 알려진 위험

모델·프롬프트로 해결되지 않았고 후속 설계(Flagger 규칙, Verifier 등)로 넘긴 위험을 모은다. 항목마다 근거 수치와 완화 방안, 상태를 적는다. 새 위험은 증거 파일과 함께 여기에 추가한다.

## KR-1. 번복이 풀리지 않은 혈압을 확정 값으로 내는 오류 (gs-003)
| 항목 | 내용 |
|---|---|
| 증상 | "백삼십 팔십이었나, 아니 백사십 팔십이었나"처럼 번복이 해소되지 않은 수치에서 모델이 값을 비우고 후보 두 개를 내지 않고 **하나(140/82 또는 140/80)를 확정**한다. flag가 ok로 나오고 사람에게 확인을 요청하지 않는다. 정답은 값 비움 + 후보 [130/80, 140/80] + 확인 필요 |
| 원인(추정) | (1) "아니"를 정정으로 읽어 마지막 값을 고름, (2) "팔십이었나"의 "이"를 숫자 2로 읽어 없는 값 82를 만듦(조사 `이`와 수사 `이` 혼동). 프롬프트 편집과는 무관함이 ablation 단계 0에서 확인됨 |
| 빈도(dev, Haiku B1, 같은 케이스 20회) | v3: 값 확정 오답 11/20(55%), v4: 13/20(65%). v3 대 v4 차이는 구분 불가(p=0.374). 정답으로 센 횟수도 후보 숫자가 틀린 경우(`130/82, 140/82`)를 포함 |
| 영향 | 혈압은 위험 필드다. 틀린 값이 확정으로 나가고 flag가 ok이면 사람 검수 대상에서 빠진다. 위험 recall 보고(61.5%)에는 반영되지 않는 오류(정답 flag가 needs_confirm인 필드의 확인 recall에서만 일부 드러남) |
| 근거 | `docs/reports/20261026-ablation-step0-gs003-b1.json`, 반복 실행 보고서(`*-haiku-*-r*.json`)의 gs-003, `docs/decisions.md` 2026-10-26 ablation 단계 0 |
| 완화 방안(미구현) | ① Flagger: transcript에 같은 항목의 숫자 두 개와 번복·불확실 표현("~이었나", "아니", "~인가")이 함께 있으면 값이 있어도 needs_confirm으로 올린다(결정적 규칙, 모델 약점을 코드로 보완). ② 모델 출력의 value가 evidence 안의 어느 숫자 조합과도 정확히 맞지 않으면(82처럼 만들어진 숫자) 강등. ③ Verifier가 숫자만 다시 읽기. ④ 번복 표현이 있는 케이스 추가(현재 gs-003, C3, C5 정도) |
| 모델별(2026-10-26 캐시 집계) | 정답이 해소 안 됨인 세 케이스에서 단일 값 확정 비율: Sonnet 0/18(단일 실행), Haiku v3 15/50, v4 22/50(v4가 더 많을 p=0.107, 탐색적). **KR-1은 Haiku에서만 관찰**된다. v4가 이 위험을 키웠을 가능성이 있다(구분 불가) |
| 완화 구현 | **구현·적용됨(2026-10-26)**: 기본 Flagger에 R1·R2. dev 캐시 재채점에서 Haiku v2~v4 조용한 오답 0, v4 0.98% → 0, F1 불변, 과다 확인 증가 0(`docs/flagger-kr1-design.md` 9장). 표본 안 결과이고 dev 밖 오경보는 단위 테스트(합성 음성 대조)로만 확인 |
| 완화 설계 | `docs/flagger-kr1-design.md`: R1 번복 의문형 표지(dev 캐시에서 단일 확정 39행 전부 포착, 오경보 0), R2 만들어진 숫자(7행 모두 오답, 오경보 0). 조용한 오답 49행 → 3행(전부 gs-015 맥박 수사 모호성). 표본 안 결과, 미구현 |
| 상태 | **부분 완화(Flagger).** 값 자체는 여전히 틀린다. 사람 확인 요청으로 넘길 뿐이다. 일반화는 test에서 처음 확인. v4 채택(2026-10-26)의 전제로 기록한다. v4가 이 오류를 악화시켰다는 증거는 없으나 개선시키지도 않았다 |
| 담당/다음 | Flagger 규칙 설계(① ②)는 API 없이 가능하므로 먼저 하고, dev 케이스에서 오류가 잡히는지 확인한 뒤 test 최종 보고 때 같은 규칙으로 측정한다 |

관련 구조 오류(별개): gs-014·015 STT가 정보를 지운 경우는 모든 프롬프트에서 같은 오답이며 Re-listener의 대상이다(`docs/decisions.md` v2 오류 분석).

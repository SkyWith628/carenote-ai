# Extractor 프롬프트 v2 설계안 (구현 전, API 호출 없이 캐시 분석만)

상태: **구현 완료(2026-10-26), 아직 측정 전**. `src/carenote/extraction/prompts.py`의 `_COMMON_V2`, CLI `--prompt v1|v2`(기본 v1). 처음 설계안 문구와 달라진 점: 시각 규칙을 "도착·방문 직후와 함께 말한 시각"으로 일반화, 숫자 한 글자씩 읽기에 한글 숫자 표(일=1…공=0) 포함, 특이사항에 "화자 본인의 컨디션" 제외 명시. 설계안의 나머지 항목은 그대로 반영.

원래 상태: 근거: dev 30건 4구성 실측(`docs/reports/20261026-dev-*.json`)의 캐시 응답 재분석. test는 보지 않았다.

## 2. v2 변경안 (정책 표를 지시문으로, 사례 문장은 쓰지 않는다)

공통부 `_COMMON`을 아래처럼 바꾼다. `PROMPT_VERSION = "v2"`로 올려 캐시를 분리한다.

1. **기분** (#10): "화자가 감정·표정·기색을 직접 말했을 때(웃으심, 밝은 표정, 기운 없어 보임)만 inferred. 대화가 활발함·이야기를 많이 함·특정 화제를 즐김은 근거가 아니다. 근거가 없으면 missing. 양호/저조가 섞이면 missing이고 특이사항에."
2. **특이사항 범위** (#11): "(a) 건강·안전 이상 징후의 관찰·호소·사건·거부, (b) 후속 조치가 필요한 사정: 측정을 못 했거나 빠뜨린 사유, 복약·치료 계획이 바뀌는 예정, 재측정 예정, 재측정으로 값이 달라졌다는 내용(앞선 측정). 제외: 가사, 환경 변화, 일상 잡담, **화자 본인의 컨디션**, 사소한 일화, 단순 병원 예약 언급."
3. **추측** (#1): "'~겠죠', '아마', '~쯤일 거예요'는 사실이 아니다. 추측한 값은 value에 넣지 않고 missing."
4. **측정 두 번** (#5): "한 방문에서 같은 수치를 다시 쟀다면 마지막 값. 번복(말을 고침)과 재측정을 구분하고, 재측정은 candidates를 쓰지 않는다. 앞선 값이 높았다면 특이사항에."
5. **식사 매핑** (#9): "남김없이=전량, 반 정도=절반, 조금·몇 숟가락·두세 번 뜸·거의 못 드심=소량, 전혀 안 드심=미섭취. 숟가락질 횟수로 어림해도 위에 맞춘다."
6. **숫자 읽기**: "수치를 숫자 하나씩 읽으면(일이공=120) 각 한글 숫자를 자릿수대로 아라비아 숫자로 바꾼다. 들리지 않는 자리를 추측하지 않는다."
7. **복약 거부** (#13): "거부 의사를 전하면 medication_taken=미복용과 별개로 special_notes에도 기록한다. 기록 방식을 바꾸라는 요구는 기록하지 않는다."
8. **낙상 시점** (#7, 임시 관례): "보고 시점 기준 최근 7일 이내의 낙상이면 있음. 그보다 오래된 이야기는 제외. '오늘은 안 넘어지셨다'가 있어도 최근 낙상이 함께 보고되면 있음." — 임시 관례임을 프롬프트 주석이 아니라 문서에 남긴다.
9. **시각**: "시각이 다른 행동(약을 챙긴 때, 도착 직후 등)과 함께 나와도 방문 시작으로 해석되면 visit_start." — 효과 불확실, 약하게.
10. "전해 들은 것도 말한 대로 기록" 삭제: 정책 #1·#6과 모호하게 겹친다.

넣지 않는 것: 개별 dev 사례의 문장이나 값. 예시는 dev와 test 어느 쪽에도 없는 새 문장만 쓴다(정책 문서 예시에 dev 문장이 들어 있어 그대로 복사하지 않는다).

## 3. 기대 효과와 한계 (측정 전 예측)
- 고칠 수 있다고 본 39건 중 B·C·E·F·G·J(31건)가 주 대상. 현실적으로는 20~30건 감소, F1 +1.5~2.5%p 정도를 기대한다. **예측이며 틀릴 수 있다.**
- A(8건)는 그대로 남는다. 위험 recall 61.5%도 그대로(Flagger 몫).
- **순환성 경고**: 정책은 dev 라벨링 과정에서 생겼고 v1 dev 20건이 정책 논쟁의 출처다. v2 프롬프트가 dev에서 오르는 것은 "정책을 따랐다"는 뜻이지 일반화 증거가 아니다. 일반화는 test에서 한 번만 확인한다.
- 과교정 위험: 기분을 거의 안 내게 되면 정답이 mood 양호인 케이스의 recall이 떨어진다(L1, v1 일부). 특이사항 범위 확장은 D형 FP를 늘릴 수 있다. 같은 실행에서 mood·special_notes의 FP/FN을 따로 본다.

## 4. 평가 절차
1. v2 프롬프트 구현 + 테스트(프롬프트에 정책 문구가 있는지, v1은 바이트 단위로 불변인지, 버전별 캐시 키 분리).
2. CLI에 `--prompt v1|v2` (기본 v1 유지: 기존 보고서 재현성).
3. dev 30건 4구성 dry-run 후 실행. 호출 120건, 캐시 없음. 이전 실측 단가로 환산하면 약 $0.55~0.7, 게이트 추정 최대치는 이보다 훨씬 크므로 승인액은 그때 제시한다.
4. v1 대 v2를 같은 구성끼리 `evaluation.compare`로 짝지어 비교(4쌍). 구간이 0을 포함하면 개선을 주장하지 않는다.
5. 프롬프트는 dev 오류만 보고 한 번 더 고칠 수 있다(v3까지). test는 마지막 1회, `--final-report`.

## 5. 사용자 판단 3건 (2026-10-26 확정)
1. **gs-019**: 정답 유지(특이사항 없음). #11에 "필드가 이미 담는 내용은 특이사항에 중복 기록하지 않는다(복약 거부만 #13 예외)" 추가. 프롬프트 v2에 같은 문장을 넣는다. 정답이 바뀌지 않았으므로 v1 결과도 그대로 유효하고, 모델의 기억 저하 기록 2건은 과다 기록으로 센다.
2. **C2**: 재측정으로 값이 달라지면 앞선 측정을 특이사항에 기록(값 차이만 기준). C2 정답 유지, `gray_fields` 해제. 프롬프트 v2 2번 항목의 "앞선 측정이 비정상이었다" 문구를 "재측정으로 값이 달라졌다"로 바꾼다. 같은 조건의 다른 케이스는 없음(전수 확인). 영향 범위: C2 strict 지표에 이제 포함.
3. **낙상 7일**: 프롬프트 v2에 넣는다(임시 관례). 보고서에서 N1·N2(낙상 시점 케이스)를 분리해 "임시 관례에 따른 점수"로 표시한다. 현장 확인으로 기준이 바뀌면 프롬프트와 정답을 함께 바꾼다.

세 결정 모두 모델 출력을 본 뒤에 내렸다. 정답은 gs-019·C2에서 바뀌지 않았고 바뀐 것은 정책 문장과 C2의 gray 표시뿐이다.

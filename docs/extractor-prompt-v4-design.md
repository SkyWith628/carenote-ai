# Extractor 프롬프트 v4 설계안 (구현 전, API 호출 없음)

상태: **구현 완료(2026-10-26), 아직 측정 전**(`PROMPT_VERSIONS`에 v4, `--prompt v4`). v2·v3 본문은 sha256으로 고정. 구현이 설계와 다른 점: 숫자 읽기 새 예시는 `일삼오 → 135`, `칠오 → 75`(`구공`은 G2 transcript에 있어 뺐다). 판정 방식은 아래 6장. 원래 설계 상태: 설계안. 근거는 **dev 30건**의 캐시된 v2 프롬프트 응답(`docs/reports/20261026-dev-v2-*.json`)과 현재 정답(동결 v2.0)뿐이다. **test 30건은 보지 않았고 test 결과도 없다**(모델 실행 0회). v3(기분 추측 허용)는 아직 측정하지 않았다.

## 1. dev에 남은 오류 (v2 프롬프트, 4구성 합계 22건)

| 원인 | 건수 | 케이스 | 프롬프트로 고칠 수 있나 |
|---|---|---|---|
| A. STT가 정보를 지움 | 9 | gs-014(4), gs-015 혈압(4), gs-015 맥박(1)* | 아니오 (구조적, Re-listener 몫) |
| B. 추측 표현이 붙은 기분을 비움 | 3 | gs-002 (Sonnet B1, Haiku B0·B1) | v3가 이미 해결 대상(미측정) |

\* gs-015 맥박: 본문 "칠십이고"에서 Sonnet B1이 70(칠십 + 이고)로 읽었다. 정답은 72(사용자 결정). 한국어 조사와 수사가 겹치는 진짜 모호성이라 프롬프트 규칙으로 풀지 않는다.

## 2. v4 변경안 (v3 기반, 5곳 + 정책 2곳)

v3의 본문 위에 아래를 더한다(바꾸는 줄은 v3 본문과 대조해 구현). 예시는 dev·test 어느 transcript에도 없는 새 문장만 쓴다.

**dev 오류에서 나온 것 (근거 있음)**
1. 식사 매핑(E): `전혀 안 드심·거부=미섭취`를 `전혀 안 드심·못 드심·안 드심(정도 표현 없이)·거부=미섭취`로. 정도가 있으면("거의 못 드심", "몇 숟가락") 소량.
2. 특이사항 (b)(C): "측정을 못 했거나 빠뜨린 사유"에 `잊었거나 값을 기억하지 못한다는 말`을 명시. 해당 필드가 missing이고 그 이유가 말로 나오면 특이사항에 한 줄.
3. 특이사항 중복(D): `복약 필드가 담는 내용(복용·미복용·중복 복용 의심)의 이유나 정황은 특이사항에 적지 않는다. 예외: 복약 거부 의사`. v2의 일반 규칙을 복약에 구체화.
4. 숫자 한 글자씩 읽기(F): 변환표는 유지하고 새 예시 두 개를 더한다(`일삼오 → 135`, `구공 → 90`, 가운데 자리를 건너뛰지 않는다). 효과는 불확실하다(모델 오독이면 안 고쳐질 수 있다).
5. 확인 누락(정책 #11(b) 확장): "확인·질문을 못 한 항목"을 (b)에 추가. v2 응답이 이미 그렇게 행동했으므로 명문화 성격이다.

**정책에서 온 것 (dev 오류 근거 없음, 사용자 요청)**
6. 정책 #14: `오늘 복약을 화자가 직접 보거나 직접 들은 경우만 기록한다. 평소 관행이나 제3자의 일반적 전언은 사실이 아니므로 missing`. "오늘 아침에 드렸대요" 같은 구체적 전언은 정책이 미정이라 규칙에 넣지 않는다.
7. v3의 기분 규칙(추측 표현 허용)은 그대로 승계.

**주의**: 6번 규칙은 test 케이스 H6의 라벨링 과정에서 나온 정책이다. v4가 test에서 좋은 점수를 내더라도 H6 한 건에는 이 정책이 반영돼 있어 test가 완전히 독립이라고 말할 수 없다. 최종 보고에서 H6에 대해 이 사실을 표시한다(H6는 어차피 잠정 동결 규칙으로 헤드라인에서 제외 예정).

## 3. 하지 않는 것
- 개별 dev 문장·값을 프롬프트에 복사하지 않는다(테스트로 전수 검사, v2와 같은 방식).
- STT 오류(A) 대응이나 gs-015 수사 모호성 규칙을 넣지 않는다.
- v2·v3 본문은 바꾸지 않는다(sha256 고정). v4는 새 버전으로 만든다.

## 4. 기대와 위험
- 기대: dev 오류 22건 중 최대 10건 감소(B 3, C 2, D 2, E 1, F 0~2). F1 +1~1.5%p 정도. **예측이며 틀릴 수 있다.** 이미 구간이 넓어 v2 대비 구분되지 않을 가능성이 높다.
- 순환성: 1~5번은 dev 오류를 보고 만든 것이므로 dev 개선은 일반화 증거가 아니다. test 1회로만 확인한다.
- 과교정 위험: 2번은 특이사항 FP(잡담·본인 컨디션)를 늘릴 수 있고, 3번은 정당한 복약 관련 특이사항(예: 복약 중 부작용 호소)까지 막을 수 있다. 같은 실행에서 special_notes의 FP/FN을 따로 본다.
- 순위가 바뀔 수 있다: v1 → v2에서 Haiku가 더 많이 올랐다. 모델별로 효과가 다르다는 점은 짝지은 비교로 본다.

## 5. 측정 계획 (승인 후)
1. 구현: `PROMPT_VERSIONS`에 v4 추가, v2·v3 해시 고정 테스트 유지, v4 정책 문구와 "dev·test 문장 미복사" 테스트.
2. dev 30건 4구성 dry-run 후 실행. 호출 120건(캐시 없음). v2 실측 실제 비용이 $0.676이었으므로 비슷한 수준이 예상된다. 게이트 최대 추정치는 v2와 같이 Sonnet 각 약 $1.4, Haiku 각 약 $0.07이므로 같은 승인액이 필요하다.
3. v2 대비·v3 대비 짝지은 비교(4쌍씩). 구간이 0을 포함하면 개선을 주장하지 않는다.
4. v3 단독 효과를 알고 싶으면 v3 4구성 측정(약 $0.7)을 먼저 해야 한다. v4만 재면 v3의 기분 규칙과 1~6번의 효과를 분리할 수 없다.
5. test는 동결 규칙대로 최종 ablation 때 한 번만(`--final-report`).

## 6. 판정 방식: 목표 필드의 반복 실행 재현 (사용자 결정 2026-10-26, 결과를 보기 전에 확정)
전체 F1이 아니라 **목표 필드의 정답 횟수**로 판정한다. 근거: Haiku 반복 실행에서 F1의 σ_run이 0.4~0.6%p라 +1%p 안팎은 노이즈와 구분되지 않는다(`docs/decisions.md`).

| 목표 필드 | 역할 | 기준(v3 5회 정답 횟수) |
|---|---|---|
| gs-018 식사(meal_intake) | **회귀 방지**: Haiku는 v2·v3 모두 5/5라 개선 여지가 없다(오류는 Sonnet B0 단일 실행에서 1회) | Haiku B0 5/5, B1 5/5 |
| gs-008 특이사항(special_notes) | 개선 대상: 잊었다·기억 못 한다 사유 | Haiku B0 2/5, B1 5/5 |
| gs-019 특이사항(special_notes) | 개선 대상: 복약 필드가 담는 이유의 중복 기록 금지 | Haiku B0 0/5, B1 4/5 |
| gs-002 기분(mood) | v3 효과 유지 확인(회귀 방지) | B0 5/5, B1 5/5 |

- **측정 설계**: v4를 Haiku B0·B1에서 5회씩(run 0 + 추가 4회, 10회, 약 $0.25 예상) 실행하고 기준은 이미 있는 v3 5회다. 개선 여지가 큰 곳은 B0(gs-008 2/5, gs-019 0/5)이고 B1은 대부분 이미 맞아 회귀 방지 역할이다.
- **사전 판정 기준**(`evaluation.variance --vs ... --targets CASE:FIELD`): 새 프롬프트가 모든 실행에서 맞고 기준은 많아야 1번 맞으면 "재현(개선)"(5회 대 5회 피셔 단측 p ≤ 0.024), 새 80% 이상·기준 40% 이하는 "개선 경향", 기준 80% 이상인데 새가 40% 이하면 "회귀", 둘 다 80% 이상이면 "유지", 그 밖은 "구분 불가".
- 회귀 방지 필드(gs-018 식사, gs-002 기분)가 "회귀"로 나오면 v4의 다른 개선과 상관없이 v4를 채택하지 않는다.
- 전체 F1은 보조 정보로만 낸다(주장하지 않음).
- 한계: gs-019 특이사항은 B1에서 이미 4/5라 B1에서는 입증할 수 없다. 정책 #14 규칙은 dev 케이스에 대응 목표 필드가 없어 이 방식으로 판정할 수 없다(test의 H6에서만 확인 가능하고 H6는 헤드라인 제외 예정).
- 비용: dry-run 결과 v4는 v2·v3와 같은 규모(Haiku 실행당 추정 최대 $0.07).

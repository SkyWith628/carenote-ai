# Sentinel R-set 설계: 독립 평가용 위험 신호 40건 (스펙 설계와 비용 dry-run, API 호출 없음)

날짜 2026-10-27. 스펙은 `data/golden/rset/specs/probe_K.json`(40건, 모델에 노출된 적 없음, transcript 없음), 생성표는 `data/golden/rset/build_specs.py.txt`.

## 1. 왜 새로 만드는가
- Sentinel 규칙의 어휘와 dev 케이스를 같은 사람이 보며 맞췄고, 정책 표는 test R2·R3 스펙에서 나왔다. 기존 60건에는 이 규칙의 **독립 증거가 없다**(`docs/rule-engine-sentinel-design.md` 6장, 재채점 13/13은 표본 안).
- 기존 골든셋·`FROZEN.json`은 건드리지 않는다. R-set은 `data/golden/rset/`에 따로 둔다(`load_golden`은 최상위 `*.jsonl`만 읽으므로 섞이지 않는다).

## 2. 구성 (40건 = dev 20 + test 20)
| 구분 | dev | test | 내용 |
|---|---|---|---|
| 양성 | 10 | 10 | 흉부·호흡 4, 신경·의식 4, 식사·수분 4, 신체 변화 4, 낙상 후 2, 정황 2 (분할마다 절반씩) |
| 어려운 음성 | 10 | 10 | 부정 3, 조언·가정 2, 제3자 2, 만성 통증 3, 과거 사건 2, 낙상 부정 2, 기간 없는 식사 2, 어휘만 닮음 2, 위험 아닌 기록 2(복약 거부 의사, 기분 변화) |

- **표현 층(양성)**: `lexicon`(규칙 어휘에 가까운 표현) 10건, `novel`(같은 위험을 규칙 어휘 밖으로 표현) 10건. novel 스펙은 `must_not`에 규칙 어휘를 넣어 생성기가 그 말을 쓰지 못하게 한다(예: 붓기 → "발등이 빵빵하고 양말 자국이 깊다", 사흘 → "금요일부터 오늘 화요일까지"). 목적은 규칙이 못 보는 영역의 크기를 재는 것이다.
- **수치는 전부 정상**(혈압 110~132대, 맥박 66~92). 혈압 임계값은 전문가 기준이 없어 내가 정한 정답으로는 독립 평가가 되지 않는다. 임상 타당성은 R-set 범위 밖이다.
- **정황 2건(K19·K20)**은 `field_review_required`: 정답 자체가 전문가 확인 전이라 헤드라인에서 제외하고 따로 보고한다.
- **gray 4건**(K24·K25 조언 안내, K31 과거 병력, K38 비유 표현): 특이사항에 적을지 정책이 갈릴 수 있어 `gray_fields`로 표시한다. 오발동 집계는 gray 제외·포함을 모두 보고한다.
- 다른 필드: 기분은 전부 missing, 나머지는 stated(복약 복용·낙상 없음이 기본, K17·K18은 낙상 있음=risk, K39는 미복용=risk, K34는 낙상 없음 + needs_confirm). 스타일(화자·지역·말더듬)은 40건이 서로 다르다.

## 3. 사전 등록 (결과를 보기 전)
**예측** (틀려도 지우지 않는다):
| 층 | 예측 | 근거 |
|---|---|---|
| 양성 lexicon, 정황 제외 (dev 4·test 4 → 8) | recall ≥ 75% | 어휘에 가까워도 생성기가 말을 바꿔 쓸 수 있다 |
| 양성 novel, 정황 제외 (dev 4·test 5 → 9) | recall ≤ 30% | 어휘 밖으로 쓰게 했다 |
| 음성 오발동 | 최소 K32(과거 낙상이 post_fall에 걸림, post_fall에는 past_event 가드가 없다)와 K38(비유 "가슴이 아프")가 발동 | 규칙 구조상 |
| 나머지 음성 | 오발동 0~1 | 가드가 설계된 대상 |

**지표** (Sentinel 단독은 transcript만 보므로 추출기 비용 0):
1. 헤드라인: 양성 18건(정황 제외)의 특이사항 risk 포착률 + Wilson 95% 구간. 18/18이어도 하한은 약 82%, 17/18은 74%로 구간이 넓다.
2. 층별: lexicon / novel, 분류별.
3. 음성 오발동 건수와 구간(0/20이면 상한 16%, 1/20이면 1~24%). gray 제외·포함 둘 다.
4. 정황 2건은 별도 줄.

**판정 규칙**:
- novel recall이 dev에서 50% 미만이면 LLM 보조 단계(근거 인용 필수)를 설계한다. 예측대로면 이 분기로 간다.
- 규칙 수정은 **dev R-set 결과로만** 한다. 그 뒤 규칙을 git 태그(`sentinel-rules-v1`)로 동결하고 test R-set은 한 번만 채점한다. 수정 이력은 decisions.md에 남긴다.
- test 20건 transcript는 생성 후에도 열어 보지 않는다(캐시에만 둔다). dev만 열람한다.
- 어떤 수치로도 "안전하다"는 결론을 내리지 않는다. 신뢰구간과 한계를 같이 쓴다.

## 4. 정답 품질 (이 단계가 병목)
- 생성 후 기존 자동 점검(A~K) → **블라인드 모델 라벨러**(정답 없이 라벨)로 특이사항 값·risk 판정이 스펙과 맞는지 확인한다. 불일치는 자동 수정하지 않고 사람이 본다.
- 사람 확인 권장 표본: gray 4건 + 정황 2건 + novel 중 라벨러와 불일치한 건 (대략 8~12건, F2 미충족 상태이므로 사람 확인이 필요하다).
- 지금까지의 한계가 그대로 있다: 사람 라벨 일치 약 93%(불일치 하한 약 7%), 단일 라벨러, 생성기·평가가 같은 Claude 계열.
- 새 편향: **스펙을 규칙 작성자(나)가 썼다.** novel 층은 이를 줄이려는 장치지만, 내가 상상한 "다른 표현"에 한정된다. 더 독립적으로 하려면 사용자가 직접 transcript 몇 건을 쓰는 것이 낫다(작성 권장: novel 양성 4 + 음성 4 = 8건, 해당 스펙은 `author: human`으로 바꾸면 생성에서 빠진다).

- 실측 보정 근거: 이전 생성 첫 실행은 19회 호출에 $0.997(호출당 약 $0.052), 블라인드 라벨러는 건당 $0.044~0.047(추정 최대는 건당 약 $0.087). 40건 × 호출당 $0.052 ≈ $2.1, 재시도 1.3배면 $2.7.
- 승인액은 게이트상 **추정 최대 이상**이어야 실행된다: 생성 $4.20 이상, 라벨러 약 $3.6 이상(실제는 그 절반 안팎). 한 번에 승인하지 말고 dev 20건 먼저 → 결과 확인 → test 20건 순서를 권한다.
- 사용자가 8건을 직접 쓰면 생성 32건으로 줄어 위 생성 비용이 약 20% 줄어든다.
- 위 추정은 Opus의 추론 토큰량을 모르는 범위 추정이다. 생성이 실패하거나(`api_failure` 비중이 높았던 적이 있다) 점검에 걸리면 재시도가 늘 수 있다.

## dev 20건 Sentinel 채점 결과 (2026-10-27, 규칙 수정 없음, 비용 0, test 없음)
채점 스크립트 `data/golden/rset/score_dev.py.txt`. 규칙은 커밋 `e3bc748` 그대로다. 정답은 스펙(모델 라벨러가 20/20 일치 확인, K26은 모호).

| 층 | 사전 등록 예측 | 실제 | Wilson 95% |
|---|---|---|---|
| 양성 lexicon (정황 제외, 5건) | recall ≥ 75% | **2/5 (40%)** — 예측 빗나감 | 12~77% |
| 양성 novel (정황 제외, 4건) | recall ≤ 30% | **0/4 (0%)** — 예측과 일치 | 0~49% |
| 헤드라인(정황 제외 9건) | – | **2/9 (22%)** | 6~55% |
| 정황 양성(K19) | 미포착 | 0/1 | – |
| 음성 오발동 | 최소 K32 발동, 나머지 0~1 | **3/10 (30%)**: K21·K25·K26. **K32는 미발동**(예측 빗나감) | 11~60% |
| 음성 오발동, gray(K25·K26) 제외 | – | 1/8 | 2~47% |

**놓친 lexicon 3건은 어휘 문제가 아니라 패턴의 모양 문제다** (패턴 단계에서 매치 자체가 없음, 가드 때문이 아님):
- K05 "말씀이 평소랑 달리 자꾸 꼬이고 어눌하셔서": `말씀이`와 `꼬이`/`어눌` 사이에 낀 말("평소랑 달리 자꾸")을 허용하지 않는다.
- K09 "식사를 또 안 하셨어유, 이게 나흘째여유": 기간이 거부 뒤에 오고, 동사가 "안 하셨"(규칙은 안 드/못 드/안 먹/거부)이다.
- K13 "두 다리가 갑자기 퉁퉁 부어": 규칙은 `갑자기`와 `퉁퉁` 중 하나만 허용한다.

**오발동 3건은 가드의 범위 문제다**:
- K21 "가슴이 답답하거나 숨이 차거나 그런 건 없으셨다고": 부정이 증상 바로 뒤가 아니라 나열 끝에 온다. 부정 가드는 증상 직후만 본다.
- K25 "혹시 팔에 힘이 빠지거나 말이 어눌해지면 바로 119에 전화하시라고": 앞 증상(말이 어눌)은 막혔지만 `면`이 8자 창 밖에 있는 뒤 증상("팔에 힘이 빠지")은 통과했다. 조언 단어에 '119'도 없다.
- K26 "어제 할아버지가 가슴이 답답하다 해서": 제3자 목록에 '할아버지'가 없다(스펙은 남편분이었으나 생성기가 호칭을 바꿨다).

**해석**
- dev 3/3·오발동 0(이전 프로토타입·재채점 13/13)은 규칙을 맞춘 케이스 안의 결과였고, **새 문장에서는 lexicon에서도 40%**였다. 정규식은 같은 의미의 어순·조사·동사 변형에 취약하다. 이 숫자를 안전성의 근거로 쓰면 안 된다.
- 사전 등록 판정 규칙: novel recall이 dev에서 50% 미만(0/4)이므로 **LLM 보조 단계 설계로 간다**. 다만 lexicon이 예측(75%)보다 훨씬 낮아, 정규식 패턴 자체를 일반화하는 개선(어순·동사 변형, 부정 범위)도 먼저 필요하다.
- 표본이 작다(양성 9, 음성 10). 구간이 넓어 "40%"와 "75%"의 차이도 구간이 겹친다(12~77%). 방향은 분명하지만 정밀한 수치는 아니다.
- 규칙 수정은 dev R-set 결과로만 하기로 했으므로 지금부터 수정할 수 있다. 수정한 뒤 dev 점수는 in-sample이 되고, test R-set(미생성)만 독립 평가로 남는다.

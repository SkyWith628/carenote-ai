# 케어노트AI: 고령 실무자의 발화 적응·음성 환각 억제 연구안

작성일: 2026-09-18. 연구 조사와 설계 제안이며 학습·재현 실험은 아직 수행하지 않았다.

## 1. 추천 연구 주제

**고령 실무자의 방언·생활어 인식을 개선하면서, 말하지 않은 돌봄 용어가 기록에 삽입되는 것을 억제하는 음성인식 모델 적응.**

주요 질문은 ‘사투리를 얼마나 잘 받아쓰는가’와 ‘실제로 말하지 않은 단어를 얼마나 덜 쓰는가’를 동시에 개선할 수 있는가다. 우선 Whisper의 경량 파인튜닝과 발화/비발화 균형 학습을 구현하고, 연구 확장은 음향 근거를 학습하는 용어 검출기로 잡는다.

LoRA·비음성 학습·키워드 검출 자체는 선행연구에 있다. 이를 최초 발명이라고 주장하지 않는다. 직접 기여할 영역은 한국어 돌봄 발화 데이터, 발화 유무를 구분한 혼동 사례, 실제 발화 보존을 고려한 학습·선택 기준, 미학습 화자 평가다. 제안한 결합의 학술적 신규성은 추가 유사연구 조사와 실험 후 판단해야 한다.

## 2. 문제를 분리해야 학습 목표가 명확해진다

| 문제 | 예 | 필요한 대응 |
|---|---|---|
| 음향·발음 차이 | 작은 목소리, 긴 쉼, 말끝 약화, 지역 억양 | 실제 음성으로 인코더/어댑터 적응 |
| 희귀 어휘 | 방언·세대별 생활어·돌봄 현장 표현 | 음성-표기 대응과 용어 존재 여부 학습 |
| 의미 변환 | 일상 표현을 기록 양식의 표현으로 정리 | 원문을 보존한 별도 의미 매핑 |
| 비음성 환각 | 물소리·무음에 문장이 생성됨 | 비음성 학습·출력 억제 |
| 발화 중 삽입·왜곡 | ‘안 드심’의 ‘안’ 탈락, 없는 조치 추가 | 중요 사실 평가·모호 구간 확인 |
| 다른 사람의 실제 말 | TV·보호자 음성을 실무자 말로 기록 | 목표 화자·녹음 상황 문제로 별도 관리 |

‘고령’, ‘사투리’, ‘발음이 불명확함’을 같은 속성으로 보지 않는다. 건강한 고령 화자와 장애·질환 화자는 다르며, 아래 한국어 ASD 연구는 학습 방법의 참고일 뿐 고령자의 특성을 입증하는 자료가 아니다. ‘고전어휘’는 중세국어까지 포함하는 표현이므로 프로젝트에서는 실제 인터뷰에서 수집한 ‘세대별 생활어·지역어’로 구체화한다.

## 3. 방법 1 — 고령·방언 음성에 LoRA/Adapter 파인튜닝

### 근거

[Fine-tuning Strategies for Automatic Speech Recognition of Low-Resource Speech with Autism Spectrum Disorder](https://www.isca-archive.org/interspeech_2025/park25g_interspeech.html), Park & Lee, Interspeech 2025. 한국어 소규모 특수 발화에서 전체·부분·Adapter·LoRA 학습을 비교했다. LoRA/Adapter의 효율적 적응 가능성을 뒷받침하지만 고령 방문요양에 대한 직접 검증은 아니다.

### 직접 구현할 부분

- Whisper-small 등 반복실험 가능한 크기에서 시작하고, 원 모델은 고정한 채 attention projection의 LoRA 가중치를 학습한다.
- encoder-only, decoder-only, 양쪽 LoRA를 비교해 발음 적응과 문장 패턴 적응을 구분한다.
- 학습 정답은 ‘말한 그대로의 전사’로 만든다. 표준어 문서로 바꾸는 작업은 분리한다.
- 일반 한국어 음성을 함께 사용해 특정 지역·문장에 과적합하거나 기존 성능을 잃는지 확인한다.

학습 데이터는 음성-수동 검수 전사 쌍이다. 정답에 없는 부정어를 임의로 보완하지 않는다. 단순히 속도를 늦추거나 피치를 낮춘 합성 음성을 ‘고령 발화’로 취급하지 않는다.

**직접 학습 가능성 높음 / 단독 독창성 낮음~중간.** 자체 돌봄 데이터와 중요 사실 오류 분석이 있어야 응용 기여를 설명할 수 있다.

## 4. 방법 2 — 비음성을 글로 만들지 않도록 모델 학습

### 근거

[Calm-Whisper: Reduce Whisper Hallucination On Non-Speech By Calming Crazy Heads Down](https://www.isca-archive.org/interspeech_2025/wang25b_interspeech.html), Interspeech 2025. 저자들은 디코더 attention head를 조사하고 일부만 비음성-빈 전사 쌍으로 튜닝했다. [방법 본문](https://arxiv.org/html/2505.12969v1)은 105시간의 비음성 학습을 기술한다. 환경음·영어 평가 결과를 한국어 돌봄 성능으로 옮겨 인용할 수는 없다.

### 우리 실험

1. 물소리·식기·환풍기·발소리·빈 방 녹음을 수집하고 실제 말소리 포함 여부를 검수한다.
2. 비음성은 빈 전사, 실제 발화는 원래 전사를 정답으로 둔다.
3. 쉬운 시작점은 동일 LoRA에 두 종류를 섞는 학습이다. 이것은 Calm-Whisper의 정확한 재현이 아니라 해당 연구에서 착안한 변형이다.
4. 심화 단계에서 head별 개입과 제한적 업데이트를 구현한다. 논문의 head 번호를 다른 모델에 그대로 적용하지 않는다.

빈 정답의 종료·비발화 토큰 처리는 모델 학습 형식에 맞춘다. 모든 라벨을 무시하도록 마스킹하면 억제 학습 신호가 생기지 않는다. 불명확하지만 실제 발화가 있는 샘플에 빈 정답을 주지 않는다.

**직접 학습 가능성 중간~높음 / 위험은 실제 발화 삭제.** 비음성 환각률만 낮추는 모델은 항상 빈 문자열을 내도 좋은 점수를 얻는다. 작은 목소리·긴 쉼이 있는 실제 문장의 보존율을 반드시 함께 측정한다.

## 5. 방법 3 — 음성에서 들린 용어만 선택하는 학습형 검출기

### 근거

[CB-Whisper: Contextual Biasing Whisper Using Open-Vocabulary Keyword-Spotting](https://aclanthology.org/2024.lrec-main.262/), LREC-COLING 2024. Whisper 음향 특징과 키워드 특징의 대응을 CNN으로 학습한 뒤 검출된 단어를 전사에 활용한다. 영어·중국어 등에서 평가되었으며 한국어 생활어 성능은 별도 확인이 필요하다.

[Adding User Feedback To Enhance CB-Whisper](https://www.isca-archive.org/interspeech_2024/monteiro24_interspeech.html), Interspeech 2024와 [저자 코드](https://github.com/Priberam/Enhance-CB-Whisper)는 자연발화 예시를 반영하는 후속 구현의 출발점이다. 코드 구조와 공개 여부는 확인했지만 실행·한국어 호환성·라이선스 적합성은 아직 검증하지 않았다.

### 직접 만들 부분

‘이 녹음에 이 표현이 실제로 존재하는가’를 판정하는 작은 KWS(keyword spotting) 모델을 학습한다.

| 음성 | 후보 표현 | 정답 |
|---|---|---|
| 해당 표현을 실제로 말함 | 해당 표현 | 존재 |
| 비슷하게 들리는 다른 표현 | 해당 표현 | 부재 |
| 다른 돌봄 주제의 발화 | 해당 표현 | 부재 |
| 생활 소음만 있음 | 해당 표현 | 부재 |

입력 녹음과 사람에게 녹음받은 용어 예시의 encoder 특징을 비교하는 CNN/MLP부터 시작한다. TTS 예시는 보조로 쓰되 방언 발음이 실제와 같은지 검수한다. 확인된 후보만 디코딩 힌트로 전달하고, 자동 교체로 확정하지 않는다.

### 프로젝트별 확장 가설

**사투리·옛 표현의 인식률을 높이는 만큼 ‘미발화 용어 삽입률’을 제약하는 학습**을 제안한다. 이름 붙이기보다 다음 차이를 실험으로 증명해야 한다.

- 모든 용어를 프롬프트로 주는 방식과 비교.
- 학습형 검출기를 사용하되 비슷한 발음의 부정 예시가 없는 방식과 비교.
- 혼동 음성·미발화 용어 예시를 추가했을 때 인식률과 삽입률이 동시에 개선되는지 비교.
- 미학습 용어·미학습 화자로 일반화를 평가.

**직접 학습 가능성 중간 / 프로젝트 연구 기여 잠재력 높음.** 다만 KWS 자체와 자연음성 피드백은 기존 기술이므로 새로운 부분은 한국어 현장 혼동 사례 설계·학습 목적·실증 결과에서 찾아야 한다.

## 6. 방법 4 — 오류 위험을 예측하고 확인 요청을 선택하는 모델

### 근거

[Detecting Whisper Hallucinations with Local Confidence Contrasts](https://proceedings.mlr.press/v309/corpataux26a.html), PMLR 2026. 인접 토큰의 신뢰도 변화를 포함한 경량 특징으로 오류 검출을 연구했다. 확신도 하나로 모든 오류를 잡을 수 있다는 근거는 아니다.

### 직접 학습할 부분

- 단어별 점수·인접 점수 변화·발화 구간 비율·반복·길이·KWS 불일치를 특징으로 구성.
- 원음-전사 대조에서 얻은 실제 정답/오류 라벨로 logistic regression, gradient boosting 또는 작은 MLP 학습.
- ‘계속 전사’, ‘해당 구간 다시 듣기/말하기 요청’의 판단을 개발셋에서 조정.
- 부정·시간·수치 오류에 더 높은 확인 비용을 부여하는 선택 규칙을 비교.

전사를 고치는 모델과 오류를 찾아내는 모델은 역할이 다르다. 확인 요청은 오류율을 낮추지만 사용자에게 일을 돌려준다. 같은 확인 요청 비율에서 남는 오류를 비교하거나, 같은 허용 오류에서 자동 처리 가능한 비율을 비교한다.

**직접 학습 가능성 높음 / 작은 데이터·적은 자원으로 시작하기 좋음.** 전체 ASR 모델을 새로 학습하지 않아도 ‘우리가 학습한 모델’이라는 설명이 성립한다.

## 7. 방법 5 — 깨끗한 음성 교사와 잡음 음성 학생의 지식증류

[Listen like a Teacher: Mitigating Whisper Hallucinations Using Adaptive Layer Attention and Knowledge Distillation](https://ojs.aaai.org/index.php/AAAI/article/view/40614), AAAI 2026은 encoder 층 정보를 결합하고, 깨끗한 입력을 받는 교사와 잡음 입력을 받는 학생을 맞추는 학습을 제안한다.

우리 적용안은 검수된 발화에 가정 소음을 섞어 clean/noisy 쌍을 만들고, 학생의 전사 정답 손실과 교사 출력·특징 일치 손실을 함께 최적화하는 것이다. 전체 ALA 구조 재현과 단순 증류 변형을 구분한다. 교사도 사투리를 틀릴 수 있으므로 교사 출력만을 정답으로 삼지 않는다.

**직접 학습 가능성 중간 / 자원·구현 부담 중간~높음.** 실제 실패 원인이 소음일 때 유력하다. 없는 어휘 지식이나 모든 지역 억양을 잡음 증강만으로 해결하지 못한다. 이번 조사에서 공식 실행 코드는 확인하지 못했다.

## 8. 방법 6 — 모델 내부 표현에 개입해 환각 억제

[Whisper Hallucination Detection and Mitigation via Hidden Representation Steering and Sparse AutoEncoders](https://arxiv.org/abs/2606.07473), 2026-06 프리프린트는 encoder 특징·SAE 표현에서 환각 관련 신호를 분석하고 추론 중 표현을 조정한다. 비음성 중심 결과로, 발화 중 부정어 누락까지 해결한 연구로 해석하면 안 된다.

[Reducing Hallucinated Transcripts in Whisper via Hallucination Space Projection](https://arxiv.org/abs/2609.04561), 2026-09 프리프린트는 비음성 교정 데이터에서 얻은 부분공간으로 decoder 표현을 조정한다. 저자들도 실제 발화 오거절과 WER의 트레이드오프를 보고한다.

직접 실험할 영역은 작은 선형 분류기부터 시작하는 내부 특징 분석, 그 다음 개입 층·강도·조건부 적용이다. 특징 추출·모델 hook·학습용/검증용 분리가 필요하다. 학술적으로 흥미롭지만 최신 프리프린트의 한국어 재현성을 확보해야 한다.

**직접 연구 가능성 중간 / 재현·일정 위험 높음.** 메인 경진대회 경로보다 확장 연구 후보로 둔다.

## 9. 방법 비교와 추천 조합

아래 평가는 논문 점수가 아니라 현재 프로젝트의 범위·마감에 대한 판단이다.

| 방법 | 직접 학습 산출물 | 주 해결 문제 | 난도 | 추천 역할 |
|---|---|---|---|---|
| 발화 LoRA | ASR adapter | 억양·발음·지역어 | 중 | 필수 기준선 |
| 비음성 억제 학습 | 억제 학습 가중치 | 무음·생활음 환각 | 중~상 | 핵심 실험 |
| 음향 근거 KWS | 용어 존재 분류기 | 희귀어 인식과 용어 과삽입 | 중~상 | 독자 기여 확장 1순위 |
| 오류 위험 예측 | 경량 분류기 | 오류 구간 확인 요청 | 중 | 자원 제한 시 좋은 연구 축 |
| 잡음 증류 | 학생 ASR | 소음 환경 강건성 | 상 | 소음이 주원인일 때 |
| 내부 표현 개입 | probe·SAE·개입 모듈 | 비음성 환각 | 상 | 장기 탐색 |

대회 전에는 **발화 LoRA + 비음성 억제의 균형 실험**을 반드시 완결하고, 데이터·시간이 허용되면 KWS 확장을 한 가지 추가한다. 여섯 가지를 모두 구현할 필요는 없다. 초기 평가에서 미발화 용어 삽입이 주된 실패라면 KWS를 먼저 하고, 무음 환각이 거의 없으면 비음성 학습 비중을 줄인다.

## 10. 제안하는 자체 연구 설계

연구 질문: **방언 적응으로 얻는 인식 향상을 유지하면서 비음성·미발화 용어 삽입을 낮출 수 있는가?**

### 10.1 학습 데이터의 역할

```text
D_speech: 실제 발화와 정확한 원문 전사
D_nonspeech: 발화가 없는 소리와 빈 전사
D_keyword: 녹음·후보 용어·존재/부재 라벨
D_replay: 일반 한국어와 정확한 전사
```

단순 출발점의 목적함수 제안:

```text
L_ASR = L_발화전사 + λ L_비음성빈출력 + μ L_일반발화유지
L_KWS = BCE(용어 존재 예측, 존재/부재 정답)
```

이 식은 연구 설계 제안이며 기존 논문의 공식 손실함수를 그대로 재현한 것이 아니다. ASR와 KWS는 먼저 독립 학습한다. λ·μ는 개발셋에서 선택하며, λ가 높아져 실제 발화가 사라지는 퇴행을 중단 조건으로 둔다.

중요어 가중 손실이나 부정·수치 대조쌍 학습은 추가 가설로 남긴다. ‘안’ 토큰을 더 자주 쓰게 만드는 것이 목표가 아니다. 발화한 경우와 발화하지 않은 경우를 함께 평가해야 한다.

### 10.2 무엇이 기존 연구 적용이고 무엇이 우리 기여인가

| 기존 연구에서 가져오는 것 | 직접 만들어 검증할 것 |
|---|---|
| LoRA/Adapter | 고령 실무자의 지역·상황을 반영한 데이터 선정과 학습 실험 |
| 비음성 빈 출력 학습 | 약한 실제 발화를 보존하는 데이터 구성·λ 선택 |
| CB-Whisper 계열 KWS | 한국어 지역어·생활어의 혼동 발음과 미발화 용어 부정 예시 |
| 오류 분류 | 돌봄 중요 사실의 잔여 오류와 확인 부담을 함께 보는 선택 정책 |

논문 재현만 성공해도 학습 경험은 충분히 있다. 혁신성 주장은 우리 추가 요소를 제거했을 때 성능이 나빠지는 실험 결과로 보강한다. ‘최초’라는 표현은 현재 근거로 사용할 수 없다.

### 작게 시작하는 규모 — 충분성을 보장하는 수치가 아님

- 공개 실제 발화 5~10시간으로 첫 파이프라인 검증 후 20~50시간으로 늘리며 학습곡선 확인.
- 생활 소음 200~500클립으로 라벨·빈 출력 처리를 점검하고 독립 원천의 시험 소리 확보.
- 지역어·생활어 30~50개부터 용어당 여러 화자 예시와 유사 발음 부정 예시 수집.
- 돌봄 시나리오 100~200건부터 시작하되 같은 화자·문장의 증강본을 독립 표본으로 세지 않음.

공개 데이터가 크다고 전부 내려받을 필요는 없다. 다양한 화자·녹음환경을 우선하고, 합성 음성만으로 학습·평가를 끝내지 않는다. ‘고령 실무자 특화’ 성과를 주장하려면 해당 사용자 또는 충분히 가까운 화자의 실측이 필요하다.

## 12. 학습 구현의 출발점

- 연구 단계: PyTorch + Transformers + PEFT. [공식 ASR LoRA 가이드](https://huggingface.co/docs/peft/main/task_guides/int8-asr)를 참고하되 버전·한국어 데이터 처리는 별도 고정.
- faster-whisper는 추론 구현이다. 이를 학습 프레임워크로 쓰는 것이 아니다.
- Whisper-small에서 rank 8/16 등 작은 탐색으로 시작한다. 학습률·rank·샘플 혼합 비율은 개발셋 기준으로 결정하고 특정 값의 성공을 보장하지 않는다.
- encoder-only / decoder-only / 양쪽 LoRA 중 처음에는 하나를 기준선으로 만든 후 추가한다.
- 가중치를 변환·양자화하거나 LoRA를 합칠 때 변환 전후 전사를 다시 비교한다.
- head 개입·KWS·SAE처럼 모델 내부 동작을 바꾸면 CTranslate2에 바로 이식되지 않을 수 있다. 연구 PoC는 PyTorch 추론을 허용한다.
- GPU 종류·메모리가 미확정이므로 필요한 VRAM·학습시간은 확정하지 않는다. 작은 배치·gradient accumulation·checkpointing을 쓰고 먼저 소량 실행으로 측정한다.

산출물은 adapter 또는 분류기 가중치, 데이터 분할 목록, 학습 설정, 평가 스크립트, 오류 사례와 모델카드다. API 연결 데모와 구분되는 직접 개발 결과가 된다.

## 13. 필수 비교실험

| 실험 | 구성 | 확인할 것 |
|---|---|---|
| B0 | 원본 Whisper | 출발 오류 |
| B1 | 원본 + VAD | 간단한 전처리만으로 해결되는 범위 |
| B2 | B1 + 일반 발화 LoRA | 방언·발음 개선과 환각 악화 여부 |
| B3 | B2 + 비음성 혼합 학습 | 환각 감소가 실제 발화 삭제 때문인지 |
| B4 | B3 + 전체 용어 프롬프트 | 용어 힌트의 효과와 허위 삽입 |
| B5 | B3 + 학습형 KWS | B4 대비 근거 있는 용어 선택 효과 |
| B6 | B5 + 혼동 발음 부정 예시 | 추가 데이터 설계의 기여 |

예산이 부족하면 B0~B3를 완결한다. 가능하면 Qwen3-ASR 등 다른 원본 모델도 외부 기준선으로 넣어, 작은 Whisper만 이겨서 혁신이라고 주장하는 것을 피한다. 가중치·VAD·디코딩 설정을 고정해 모델 효과와 후처리 효과를 분리한다.

필수 지표:

1. 한국어 CER와 부정·시간·수치·행동 수행 여부 오류율.
2. 비발화 클립 중 한 글자라도 생성한 비율. 빈 정답의 WER는 분모가 0이므로 사용하지 않음.
3. 실제 발화를 빈 출력으로 지운 비율과 발화 내부 삭제 오류율.
4. 용어 recall과 precision, 용어를 말하지 않은 사례에서의 허위 삽입률.
5. 미학습 화자·지역·용어·소음원 각각의 결과.
6. 확인 요청률, 확인 후 남은 오류, 전체 과업시간.

‘덜 출력해서 정확해진 것’을 개선으로 오인하지 않는다. 학습/개발/시험은 화자·원천녹음·문장·소음원 누출을 막고, 같은 원음의 변형은 같은 분할에 둔다. 최종 시험을 보고 λ나 임계값을 다시 맞추지 않는다. 가능하면 seed 반복과 화자 단위 신뢰구간을 보고한다.

## 14. 경진대회 일정에 맞춘 범위

- 1주차: 데이터 접근·표기 정책·미학습 화자 시험셋, B0/B1 평가.
- 2주차: LoRA B2와 비음성 학습 B3. 실제 발화 삭제 검증.
- 3주차: 결과가 안정적이고 시간이 남으면 용어 검출기 B4~B6.
- 제출 전: 학습을 멈추고 고정 시험셋 결과·실패 사례·데모 정리.

접근 승인·GPU·실제 화자 데이터가 지연되면 B0~B3와 데이터 설계에 집중한다. 좋은 결과가 나오기 전까지 발표 문구는 ‘개발·검증할 계획’이다.

발표에서 증명할 주장 후보:

> 고령 실무자의 발화와 현장 비음성을 함께 학습해 지역어 인식을 개선하고, 존재하지 않는 기록 생성을 줄이는 모델 적응 방법을 검증한다. 실제 발화가 삭제되지 않는지도 함께 평가한다.

KWS까지 검증됐다면 다음을 추가할 수 있다.

> 돌봄 용어를 무조건 추천하는 대신, 해당 표현의 음향 근거를 학습하는 검출기를 직접 개발해 미발화 용어의 삽입을 줄였다.

후자의 과거형은 실제 실험 결과 확보 후에만 사용한다.

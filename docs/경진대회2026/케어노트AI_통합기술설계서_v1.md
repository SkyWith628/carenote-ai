작성일: 2026-09-18  
문서 상태: 경진대회용 설계·연구 계획 / 구현 및 성능 검증 전

## 1. 문서 목적과 핵심 방향

케어노트AI는 돌봄 현장 실무자의 짧은 음성 기록을 기관 양식에 맞는 기록 초안으로 변환하고, 사회복지사가 원문 근거를 확인하여 승인하는 기록 지원 시스템이다. 핵심은 문장을 그럴듯하게 만드는 것이 아니라 **실무자의 말을 정확하게 듣고, 말하지 않은 사실을 기록하지 않는 것**이다.

이 문서는 기존 기술 검토와 음성인식 학습 연구안을 통합한다. 특정 모델의 도입이나 연구 효과가 확정되었다는 뜻은 아니다. 외부 연구에서 제시된 방법과 프로젝트가 새롭게 검증할 가설을 구분한다.

| 구분 | 현재 정리한 방향 |
|---|---|
| 설계 원칙 | 원문 근거 보존, 불확실성 표시, 실무자 최종 승인, 개인정보 최소 처리 |
| 우선 구현 권고 | 짧은 단일 화자 녹음 → 자체 서버 음성인식 → 사실 추출 → 양식 초안 → 검토·승인 |
| 우선 학습 연구 | 고령 실무자·방언 음성 적응과 비음성 구간의 허위 전사 억제 |
| 선택 연구 | 음향 근거 기반 돌봄 용어 인식, 학습형 오류 위험 탐지 |
| 후순위 | 문서 생성 LLM 파인튜닝, 복잡한 에이전트 오케스트레이션, 자율 브라우저 조작 |
| 미확정 | 최종 모델, GPU, 확보 가능한 학습량, 대상 양식, 현장 참여자, 운영 보관 기간 |

기존 기획서의 ‘파인튜닝은 선택 사항’이라는 방향을 세분화한다. **문서 생성 LLM의 파인튜닝은 보류하되, 음성인식 모델의 경량 학습은 핵심 연구 후보로 우선 검토**한다. 학습 자체가 혁신성의 증거는 아니며, 기본 모델 대비 개선과 부작용을 실험으로 제시해야 한다.

## 2. 해결할 문제의 분리

‘고령자 음성인식이 어렵다’를 하나의 문제로 취급하지 않는다. 연령만으로 발음 특성이나 장애를 추정하지 않으며, 실제 사용자 자료에서 오류 유형을 확인한다.

| 문제 | 예시·구분 | 대응 방향 |
|---|---|---|
| 음향·발음 차이 | 작은 목소리, 느린 발화, 길어진 쉼, 불명확한 종성 | 실제 음성 기반 적응 학습, 약한 발화 보존 |
| 방언·생활 어휘 | 지역 표현, 오래된 생활 용어, 돌봄 현장 표현 | 원문 전사 학습, 용어 후보의 음향 검증 |
| 의미 표준화 | 현장 표현을 양식의 표준 표현으로 정리 | 원문과 표준화 결과 분리, 근거 연결 |
| 비음성 허위 전사 | 침묵·잡음만 있는데 문장이 생성됨 | 비음성 학습, VAD, 출력 위험 탐지 |
| 발화 중 중요 오류 | ‘안 드심’의 부정 누락, 횟수·시간 변경 | 중요 사실 평가, 확인 요청 |
| 배경 발화 오인 | TV·다른 사람의 말을 기록자 발화로 처리 | 초기에는 녹음 환경 제한, 별도 혼입 평가 |
| 문서 생성의 추론 삽입 | 하지 않은 보호자 연락을 수행한 것처럼 기재 | 사실·제안 분리, 수행 여부 필드, 승인 절차 |

TV의 말은 비음성이 아니다. 비음성 학습만으로 화자 구분 문제까지 해결했다고 주장하지 않는다. 또한 정확한 전사와 의미 표준화는 다른 과제다. 사투리를 처음부터 표준어로 바꾼 문장만 정답으로 사용하면 무엇이 인식 오류인지 평가하기 어렵다.

## 3. 초기 서비스 범위

### 3.1 사용자와 입력

- 요양보호사 등 기록자가 돌봄 직후 짧게 구술한다.
- 사회복지사는 사실과 누락 항목을 검토하고 기록 초안을 승인한다.
- 초기에는 단일 화자·짧은 구술·기록 양식 한 종류로 제한한다.
- 실제 수급자의 민감정보가 없는 가상 돌봄 시나리오로 개발·시연한다.

다중 화자 상담의 상시 녹음, 의료적 판단, 기록의 무검토 자동 제출은 초기 범위에서 제외한다.

### 3.2 처리 원칙

1. 음성에 없는 관찰 사실과 수행 행위를 추가하지 않는다.
2. 애매한 부분은 임의로 확정하지 않고 원문 구간과 함께 확인 요청한다.
3. 원문 전사·추출 사실·양식 문장을 별도로 보관한다.
4. 승인 전 초안과 승인된 기록을 구분한다.
5. 음성은 자체 운영 서버에서 처리하는 것을 우선 검토한다. 이는 휴대폰 내부에서 처리하는 ‘온디바이스’와 다르다.
6. 외부 LLM을 이용할 경우 전송 전 개인정보를 최소화·가명화한다. 자동 마스킹만으로 완전한 비식별화를 보장하지 않는다.

## 4. 권장 시스템 구성

| 단계 | 처리 | 주요 산출물·통제 |
|---|---|---|
| 1. 녹음 | 모바일 웹에서 녹음·재생·업로드 | 사용자 확인을 거친 음성, 녹음 식별자 |
| 2. 전처리 | 포맷 변환, 구간 분리, VAD | 원본 시간과 연결된 구간; 작은 목소리 누락 점검 |
| 3. 음성인식 | 자체 서버의 ASR 모델 | 원문 전사, 구간 시각, 모델 버전, 점수 |
| 4. 위험 판정 | 허위 전사·용어·중요 표현 점검 | 재청취 또는 재입력이 필요한 구간 |
| 5. 사실 추출 | 개인정보 최소화 후 구조화 | 관찰 사실, 부정, 시점, 수행 여부, 근거 |
| 6. 양식 작성 | 필드 검증과 템플릿 적용 | 양식 초안, 누락 항목, 별도 확인 질문 |
| 7. 검토·승인 | 음성·원문·초안을 나란히 확인 | 수정 이력과 승인된 버전 |
| 8. 선택 연계 | 시연용 양식에 확정 값 입력 | 입력 후 재확인; 무인 자동 제출 제외 |

### 4.1 웹·앱과 서버의 역할

초기에는 Next.js 기반 반응형 웹을 권고한다. 브라우저의 MediaRecorder로 녹음하되, 기기별 지원 MIME 형식, 마이크 권한, HTTPS, 업로드 실패와 재시도를 검증한다. 네이티브 앱은 오프라인 녹음이나 백그라운드 동작 등 실제 요구가 확인되면 검토한다.[T1]

FastAPI는 녹음 접수와 작업 상태 조회를 담당하고, 음성인식은 별도 작업 프로세스에서 수행한다. 사용자의 승인까지 HTTP 요청을 유지하지 않는다. 프런트엔드는 작업 상태를 조회하여 결과와 검토 화면을 표시한다.

작업 상태의 제안은 `uploaded → transcribing → extracting → needs_review → approved`이다. 정보가 부족하면 `needs_info`, 처리 실패는 `failed`로 분리한다. 같은 업로드의 재시도가 중복 기록을 만들지 않도록 식별자를 사용한다. 승인 후 내용이 바뀌면 새 버전을 만들고 재승인을 요구한다.

### 4.2 에이전트와 프레임워크

초기 시스템은 고정된 처리 절차와 명시적 검증 규칙으로 충분하다. 에이전트가 필요하다면 ‘누락된 항목 확인’, ‘근거 구간 요청’, ‘양식 선택’처럼 권한과 도구를 좁힌다. 규칙이 정해진 필드 채우기를 자율 추론으로 바꿀 필요는 없다.

LangGraph는 복잡한 분기·중단·재개·상태 보존이 필요할 때 도입한다. 프레임워크 사용만으로 느리다고 단정하지 않고 모델 호출 횟수, 추론 시간, 데이터 조회, 재시도 시간을 나누어 측정한다.[T2]

## 5. 모델과 기술 선택

| 영역 | 우선 검토안 | 비교·보완안 | 판단 기준 |
|---|---|---|---|
| ASR 학습 | Whisper-small + Transformers·PEFT LoRA | 규모 확장은 자원 확인 후 | 자체 데이터에서 개선 여부, 메모리, 재현성 |
| ASR 기본 성능 비교 | Whisper large-v3 / turbo | Qwen3-ASR 0.6B·1.7B | 같은 데이터·장비의 정확도와 지연 |
| ASR 배포 | faster-whisper / CTranslate2 | 학습 체크포인트의 변환·출력 검증 | 배포 후 정확도 손실과 처리량 |
| 용어 인식 | 기본 전사와 소규모 용어집 | 학습형 음향 KWS | 용어 재현율과 없는 용어 삽입률 |
| 사실 추출 | 구조화 출력을 지원하는 LLM | 로컬 Qwen3-4B-Instruct-2507·Qwen3-8B 후보 | 사실 일치, 개인정보, 비용·지연 |
| 양식 작성 | 코드 기반 필드 매핑·검증 | 표현 다듬기에 제한적으로 LLM 사용 | 근거 없는 내용과 필수값 누락 |
| 검색 | 필요한 경우에만 PostgreSQL·pgvector | BGE-M3 등 검색 임베딩 | 검색이 실제로 필요한 질문인지 |

위 모델은 검토 후보이며 최종 선정이나 성능 순위를 의미하지 않는다. Qwen3-ASR의 한국어 지원이 한국어의 모든 지역 방언 성능을 보장하지는 않는다. 단어 수준 시각이 필요하면 정렬 기능과 추가 계산 비용도 비교한다.[R9]

faster-whisper는 추론 구현이며 학습 프레임워크가 아니다. LoRA 학습과 배포 변환을 분리하고, 변환 전후 같은 시험 데이터로 결과를 확인한다.[T3][T4]

정책·양식 검색이 필요한 경우 문서 버전과 적용일을 기록한다. 이용자의 과거 기록, 현재 관찰, 제도 문서는 서로 다른 출처다. 검색된 지침을 근거로 실제 하지 않은 돌봄 행위를 기록하지 않는다. 한국어 키워드 검색은 형태소 처리와 토큰화를 별도 검토한다.[R10]

## 6. 직접 학습할 수 있는 연구 방법

### 6.1 방법 A — 고령 실무자·방언 적응 LoRA

Whisper의 일부 가중치에 작은 학습 모듈을 추가하여 실제 대상 발화에 적응시킨다. 인코더만, 디코더만, 양쪽에 적용한 설정을 비교한다. 초기 rank 8·16 등은 탐색 시작점이지 검증된 최적값이 아니다.

학습 자료는 실제 발음을 반영한 원문 전사를 사용한다. 일반 한국어 자료를 일부 함께 학습하여 특정 화자·표현에 과적합하거나 일반 성능이 떨어지는지 확인한다. 저자원 비전형 발화에 대한 파인튜닝 연구는 방법 선택의 참고 자료이며, 다른 발화 집단의 결과를 고령 한국어 실무자에게 그대로 적용할 수는 없다.[R1]

직접 만들 부분: 대상 음성 코퍼스, 전사 지침, 어댑터 학습 설정, 화자 독립 평가, 오류 유형별 분석.

### 6.2 방법 B — 비음성 허위 전사를 억제하는 균형 학습

실제 발화뿐 아니라 침묵, 호흡, 마찰음, 생활 잡음 등 말이 없는 입력을 함께 학습하고 해당 입력에서는 텍스트를 출력하지 않도록 한다. Calm-Whisper는 비음성 입력의 환각 억제를 위한 선택적 학습의 근거다. 해당 논문의 헤드 선택 학습과 본 프로젝트의 LoRA 확장 실험은 동일한 방법이 아니다.[R2]

제안 손실 구성은 다음과 같다. 이는 프로젝트의 실험 설계이며 기존 논문의 식을 그대로 재현한 것이 아니다.

```text
L_ASR = L_실제발화 + λ · L_비음성종료출력 + μ · L_일반음성재학습
```

비음성의 ‘빈 전사’는 모든 정답 토큰을 무시하도록 구현하면 안 된다. 모델의 종료·비음성 처리 규약에 맞는 유효한 학습 목표가 필요하다. 작은 목소리, 긴 쉼을 포함한 실제 발화를 비음성으로 잘못 라벨링해서도 안 된다.

직접 만들 부분: 현장 잡음과 실제 발화의 구분 자료, 학습 비율·가중치 실험, 허위 전사 감소와 실제 말의 삭제 증가를 함께 측정하는 평가.

### 6.3 방법 C — 음향 근거가 있는 용어만 보강하는 KWS

전체 용어집을 프롬프트에 넣으면 실제로 말하지 않은 단어가 유도될 가능성도 평가해야 한다. 대안은 음성에서 해당 용어가 실제 발화되었을 가능성을 판별한 뒤, 근거가 있는 후보만 인식기에 제공하는 것이다.

CB-Whisper는 Whisper의 음향 표현을 이용한 키워드 탐지와 문맥 보강의 선행 연구다. 후속 연구는 사용자 피드백을 활용한 개선을 다룬다. 따라서 ‘키워드 탐지와 피드백을 결합했다’는 것 자체를 새로운 발명으로 주장하지 않는다.[R3][R4]

프로젝트에서는 CNN 또는 작은 MLP 등으로 다음 자료를 구분하도록 학습할 수 있다.

- 해당 용어를 실제로 말한 음성
- 발음은 비슷하지만 다른 단어를 말한 음성
- 정상 발화이지만 해당 용어가 없는 음성
- 말이 없는 잡음

용어 탐지 결과는 후보와 검토 표시로 활용하며 전사를 강제로 치환하지 않는다. **한국어 돌봄 생활 어휘의 음향 검증과 혼동 발음 음성의 대조 학습**을 구체적인 기여 후보로 삼고, 용어집만 제공하는 방식보다 삽입 오류가 줄어드는지 검증한다.

### 6.4 방법 D — 오류 위험을 학습하여 확인 요청

ASR의 토큰 점수를 정답 확률처럼 사용하지 않는다. 구간 내부 점수 변화, 반복 출력, 발화 길이, 비음성 비율, 용어 탐지와 전사의 불일치 등을 입력으로 작은 오류 위험 분류기를 학습한다. Local Confidence Contrasts 연구는 국소적 신뢰도 변화 활용의 참고 자료다.[R5]

단순 임계값 방식과 로지스틱 회귀·트리 계열·MLP를 비교한다. 확인 요청을 많이 보내면 오류가 줄어드는 것은 당연하므로, 동일한 확인 요청 비율에서 남는 중요 오류를 비교한다. 초기에는 위험 판단만 하고 내용을 자동 수정하지 않는다.

### 6.5 방법 E — 깨끗한 음성과 잡음 음성 사이의 지식 증류

같은 발화의 상대적으로 깨끗한 음성과 잡음이 섞인 음성을 준비하고, 교사 모델의 표현·출력을 학생 모델에 전달하는 방법을 검토한다. Adaptive Layer Attention과 지식 증류 연구가 참고 근거다.[R6]

교사도 방언을 틀릴 수 있으므로 사람이 확인한 정답을 함께 사용한다. 깨끗한 짝 음성 확보와 학습 비용이 추가되므로 A·B 이후 선택한다.

### 6.6 방법 F — 내부 표현 분석과 환각 억제

은닉 표현, 희소 오토인코더, 환각 관련 공간 투영을 이용하는 최근 연구를 검토할 수 있다.[R7][R8] 다만 프리프린트 단계의 결과이며 한국어 현장 자료로 재현이 필요하다. 내부 분석, 탐지기 학습, 추론 시 표현 조작은 각각 다른 작업이다.

연구 난도와 정상 발화 억제 위험이 높으므로 경진대회 필수 구현에서 제외한다. A·B가 안정화되고 비교 실험 시간이 남을 때만 수행한다.

### 우선순위 결론

**A와 B를 핵심 학습 실험으로 추진하고, C를 차별화 확장으로 검토한다.** D는 검토 화면과 연결할 수 있는 보완 연구다. E·F까지 모두 구현하는 계획은 잡지 않는다.

## 7. 데이터 구축과 분할

### 7.1 데이터 묶음

| 묶음 | 내용 | 주의 사항 |
|---|---|---|
| D_speech | 고령 실무자·방언 발화와 검수된 원문 전사 | 연령·지역 정보 수집은 필요한 범위로 제한 |
| D_noise | 실제 단어가 없는 현장 잡음·침묵 | 배경 대화나 작은 목소리를 빈 정답으로 처리하지 않음 |
| D_keyword | 용어 존재·부재, 유사 발음, 음성 구간 | 양성 예제만 모으지 않음 |
| D_replay | 일반 한국어 발화 | 적응 학습 후 기본 성능 저하 확인 |
| D_workflow | 가상 돌봄 시나리오와 정답 사실·양식 | 음성 오류와 문서 생성 오류를 분리 평가 |

공개 자료 후보는 AI Hub의 고령층 자유대화, 중장년·노년층 방언, 지역 방언 자료다.[D1][D2][D3] 다운로드 가능 여부, 이용 조건, 재배포·모델 공개 가능 범위는 사용 전에 확인한다. 공개 자료가 실제 돌봄 기록자의 발화 분포와 같다고 가정하지 않는다.

초기 수집 규모는 발화 5~10시간, 비음성 200~500개 구간, 주요 용어 30~50개, 가상 돌봄 시나리오 100~200개 정도를 계획 시작점으로 잡을 수 있다. 이후 오류와 학습 곡선을 보고 20~50시간 수준의 확대 여부를 결정한다. 이 수치는 성능 보장이나 통계적 충분성을 의미하지 않는다.

### 7.2 라벨링

- 실제 들린 원문과 양식용 표준화 문장을 별도 필드로 기록한다.
- 들리지 않는 부분은 불명확 구간으로 표시하고 정답을 추측하지 않는다.
- 부정, 수량, 시간, 대상, 관찰·수행 여부 등 중요 사실을 표시한다.
- 녹음 출처, 화자, 세션, 동의 범위, 전사 검수 상태를 기록한다.
- 가상 사례를 사용하며 실제 이용자 정보가 섞이면 별도 정제한다.
- 음높이 변환이나 합성 음성만으로 고령자·방언 자료를 대체하지 않는다.

### 7.3 누수 방지

화자와 원본 녹음 단위로 학습·검증·시험 자료를 나눈다. 동일 녹음의 잘라낸 구간과 잡음 증강본은 같은 분할에 둔다. 반복 시나리오·동일 잡음 출처가 시험 결과를 쉽게 만들지 않도록 점검한다. 최종 시험 자료는 모델·임계값 선택에 사용하지 않는다.

새로운 화자, 지역 표현, 처음 등장한 용어에 대한 결과를 따로 보고한다. 자료가 부족하면 해당 집단에 대한 일반화 주장을 제한한다.

## 8. 사실 추출·양식 작성 설계

LLM은 구조화된 사실을 추출하고, 프로그램은 필수 필드와 값의 형식을 검사한다. JSON 형식을 지킨다고 사실의 정확성까지 보장되는 것은 아니다.

```json
{
  "fact_id": "f1",
  "subject_id": "selected_recipient",
  "field": "meal_intake",
  "value": "점심을 거의 먹지 않음",
  "polarity": "negative",
  "event_time": "unknown",
  "evidence": {"segment_id": "s1", "quote": "점심 거의 안 드시고"},
  "action_status": "not_applicable",
  "review_status": "pending"
}
```

‘점심 거의 안 드시고 걸을 때 어지럽다고 하심’에서 식사량과 어지럼 호소는 추출할 수 있다. 그러나 ‘보호자에게 연락함’은 추출할 수 없다. 후속 확인이 필요하다면 기록 사실이 아닌 별도의 질문으로 제시한다. 선택된 이용자 식별자는 앱의 사용자 선택 맥락이며 음성에서 추론한 정보와 구분한다.

근거 인용이 실제 전사에 있는지는 자동 검사할 수 있지만, 인용이 해당 사실을 의미적으로 뒷받침하는지는 별도 평가가 필요하다. 의료 기록 생성 연구의 사실성 평가와 ACI-BENCH는 평가 설계 참고 자료이며 한국어 요양 양식의 정답 데이터로 직접 간주하지 않는다.[R11][R12]

### 최소 관리 데이터

| 개체 | 필요한 정보 |
|---|---|
| Recording | 녹음 ID, 접근 권한, 저장 위치, 동의·보관 정보 |
| TranscriptSegment | 시작·종료 시각, 원문, 모델 버전, 원시 점수 |
| Fact | 값, 대상, 부정, 시점, 수행 여부, 근거, 검토 상태 |
| Draft | 양식 버전, 사실 목록, 초안 버전, 승인 상태 |
| ReviewIssue | 문제 구간, 확인 사유, 사용자 수정과 처리 결과 |
| ExperimentRun | 모델·데이터 버전, 설정, 시드, 평가 결과 |

승인된 내용과 수정 이력을 보존하되, 감사 기록에 원문 개인정보를 불필요하게 중복 저장하지 않는다. 사용자의 수정이 자동으로 학습 데이터 사용 동의를 의미하지는 않는다.

## 9. 실험과 평가

### 9.1 비교군

| 실험 | 구성 | 확인할 질문 |
|---|---|---|
| B0 | 원본 ASR | 기본 오류 수준은 얼마인가? |
| B1 | 원본 ASR + VAD | 허위 전사가 줄면서 실제 발화가 잘리지 않는가? |
| B2 | B1 + 발화 LoRA | 대상 발화 정확도가 개선되는가? |
| B3 | B2 + 비음성 균형 학습 | 정상 발화 삭제 없이 허위 전사가 줄어드는가? |
| B4 | B3 + 전체 용어집 제공 | 용어 개선과 불필요한 삽입의 상충은 무엇인가? |
| B5 | B3 + 학습형 KWS 후보 제공 | 전체 용어집보다 음향 검증이 유리한가? |
| B6 | B5 + 혼동 발음 대조 자료 | 비슷한 단어의 오탐이 감소하는가? |

B5는 B4에 추가하는 방식이 아니라 용어 제공 방식을 대체하는 비교다. 각 실험의 데이터·학습량·디코딩 설정을 최대한 맞춘다. 추가로 VAD 유무와 학습 유무를 교차 비교하여 VAD 효과를 학습 효과로 오인하지 않는다. Qwen3-ASR은 같은 시험 세트와 장비 조건의 별도 비교군으로 둔다.

### 9.2 지표 정의

| 지표 | 정의·보고 방식 |
|---|---|
| CER | 문자 대치·삭제·삽입 수의 합 / 정답 문자 수; 띄어쓰기 처리 규칙 고정 |
| 비음성 허위 전사율 | 텍스트가 출력된 비음성 구간 수 / 전체 비음성 구간 수 |
| 실제 발화 무출력률 | 빈 출력이 나온 실제 발화 구간 수 / 전체 실제 발화 구간 수 |
| 발화 삭제 오류 | 실제 발화에서 삭제된 문자 수 / 정답 문자 수 |
| 용어 정밀도·재현율 | 맞게 검출한 용어와 전체 검출·실제 용어 수를 기준으로 계산 |
| 부재 용어 삽입률 | 지정 용어가 없는데 그 용어를 출력한 시험 사례 수 / 해당 용어가 없는 시험 사례 수 |
| 중요 사실 오류율 | 부정·수량·시점·대상·수행 여부의 오류를 유형별로 보고 |
| 검토 효율 | 같은 확인 요청 비율에서 남는 중요 오류, 확인에 든 시간 |
| 업무 시간 | 녹음부터 수정·재입력·승인까지 전체 시간; 역할별 시간도 기록 |
| 시스템 성능 | 동일 장비의 p50·p95 지연, 메모리, 비용; 초기 실행과 반복 실행 분리 |

정답이 빈 비음성 자료에는 일반 CER·WER를 그대로 적용하지 않는다. ‘다시 말해 달라’고 많이 요청하여 얻은 낮은 오류율은 사용성 개선과 구분한다. 허위 전사 감소와 작은 목소리 누락 증가를 함께 제시한다.

### 9.3 전체 서비스 평가

사람이 교정한 전사를 입력한 결과와 실제 ASR 전사를 입력한 결과를 모두 측정하여 음성인식 오류와 문서 생성 오류를 분리한다. 수기 작성, 음성 기반 단순 초안, 근거 확인형 초안의 작성·검토 시간을 비교한다. 같은 사용자가 여러 방식을 사용할 경우 순서를 바꾸어 연습 효과를 줄인다.

시험 규모와 참여자 수를 밝히고 가능하면 화자 단위 변동성과 신뢰구간을 제시한다. 성공 사례뿐 아니라 실패 사례, 일반 한국어 성능 저하, 지연 증가도 보고한다. 목표 수치는 기본 성능 측정 후 정하며 아직 달성 성능처럼 쓰지 않는다.

## 10. 혁신성의 주장 범위

제안할 연구 질문은 다음과 같다.

> 고령 돌봄 실무자의 발화에 적응한 음성인식 모델에 비음성 억제 학습과 음향 근거 기반 용어 선택을 적용하면, 일반 파인튜닝이나 용어집 제공보다 중요한 기록 오류를 줄일 수 있는가?

가능한 기여는 돌봄 현장의 혼동 발음·비음성 자료 설계, 학습 조합과 균형 조정, 용어 선택기, 중요 사실 중심 평가다. 기존 기술을 이용한다는 사실을 숨기지 않되 직접 만든 데이터·가중치·학습 코드·비교 결과를 구분하여 제시한다.

학술적으로 새로운 방법임을 입증한 상태는 아니다. ‘세계 최초’, ‘환각 제거’, ‘고령자 음성 완벽 인식’ 대신 ‘기존 방법 대비 개선 여부를 검증하는 현장 특화 연구’로 설명한다. 경진대회에서는 기술 차별성과 함께 실제 기록 부담 감소, 적용 가능성, 실패 시 안전한 처리까지 보여준다.

## 11. 구현 순서와 의사결정 기준

| 순서 | 작업 | 다음 단계로 진행할 근거 |
|---|---|---|
| 1 | 양식 한 종류·가상 시나리오·평가 규칙 확정 | 무엇을 정확히 기록해야 하는지 정의됨 |
| 2 | 기본 모델과 VAD 비교, 오류 자료 수집 | B0·B1 결과와 대표 실패 사례 확보 |
| 3 | 발화 LoRA와 비음성 균형 학습 | B2·B3 재현 가능, 삭제 부작용 확인 |
| 4 | 근거 기반 사실 추출·검토 화면 연결 | 원문부터 승인까지 시연 가능 |
| 5 | 여력이 있으면 KWS와 대조 학습 | 용어집 방식 대비 추가 효과 확인 |
| 6 | 잠근 시험 세트 평가·발표 근거 정리 | 성능·한계·수정 시간 결과 확보 |

GPU나 데이터가 부족하면 연구 항목 수를 줄이고 A·B의 비교 실험을 완성한다. 비음성 억제가 실제 발화 삭제를 크게 늘리면 학습 비중을 낮추거나 위험 표시 방식으로 전환한다. 작은 모델의 개선이 큰 기본 모델보다 실용적이지 않으면 정확도뿐 아니라 비용·지연·배포 조건을 비교하여 채택 여부를 결정한다.

완료 산출물은 학습·평가 데이터 명세, 재현 가능한 학습 설정, 모델 또는 어댑터, 비교 결과표, 근거 확인 화면, 성공·실패 시연이다. 전체 모델을 처음부터 학습하는 것은 목표가 아니다.

## 12. 남아 있는 결정 사항

- 실제 기록자의 연령·지역·녹음 환경과 가장 빈번한 오류 유형
- 우선 적용할 기록 양식과 필수 항목
- 음성 수집 참여자, 동의 절차, 자료 이용·보관 범위
- 사용 가능한 GPU·운영 서버와 응답시간 요구
- 비교할 기본 모델과 공개 모델·데이터의 이용 조건
- 허용 가능한 확인 요청량과 중요 오류의 정의
- 외부 LLM 사용 여부와 전송할 정보의 범위

이 항목을 확정하기 전에는 특정 학습량, 모델 크기, 정확도 목표를 고정하지 않는다.

## 13. 참고 논문·연구·공식 자료

아래는 기존 연구 검토 문서에서 정리한 출처다. 타 언어·타 집단의 효과를 본 프로젝트의 검증된 성능으로 해석하지 않는다. 프리프린트와 공식 구현 문서는 심사 논문과 구분한다.

### 음성인식과 학습 연구

- [R1] [Fine-tuning Strategies for Automatic Speech Recognition of Low-Resource Speech with Autism Spectrum Disorder](https://www.isca-archive.org/interspeech_2025/park25g_interspeech.html), Interspeech 2025. 대상 집단이 다르므로 학습 전략 참고에 한정.
- [R2] [Calm-Whisper](https://www.isca-archive.org/interspeech_2025/wang25b_interspeech.html), Interspeech 2025. 비음성 환각 억제 학습.
- [R3] [CB-Whisper](https://aclanthology.org/2024.lrec-main.262/), LREC-COLING 2024. 음향 키워드 탐지와 문맥 보강.
- [R4] [Adding User Feedback To Enhance CB-Whisper](https://www.isca-archive.org/interspeech_2024/monteiro24_interspeech.html), Interspeech 2024. [저자 구현](https://github.com/Priberam/Enhance-CB-Whisper); 사용 전 라이선스 확인 필요.
- [R5] [Detecting Whisper Hallucinations with Local Confidence Contrasts](https://proceedings.mlr.press/v309/corpataux26a.html), PMLR 2026. 오류 위험 탐지 참고.
- [R6] [Listen like a Teacher: Mitigating Whisper Hallucinations Using Adaptive Layer Attention and Knowledge Distillation](https://ojs.aaai.org/index.php/AAAI/article/view/40614), AAAI 2026. 잡음 강건성과 지식 증류.
- [R7] [Whisper Hallucination Detection and Mitigation via Hidden Representation Steering and Sparse AutoEncoders](https://arxiv.org/abs/2606.07473), 2026 프리프린트. 내부 표현 기반 연구.
- [R8] [Reducing Hallucinated Transcripts in Whisper via Hallucination Space Projection](https://arxiv.org/abs/2609.04561), 2026 프리프린트. 투영 기반 억제 연구.
- [R9] [Qwen3-ASR Technical Report](https://arxiv.org/abs/2601.21337), 2026 기술 보고서. [모델 카드](https://huggingface.co/Qwen/Qwen3-ASR-1.7B).
- 참고: [Careless Whisper: Speech-to-Text Hallucination Harms](https://arxiv.org/abs/2402.08021), FAccT 2024. 존재하지 않는 내용의 전사 위험.

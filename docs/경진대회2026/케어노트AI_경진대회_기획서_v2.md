## §0. 프로젝트 재정의

### 0.1 한 줄 정의

> **케어노트AI는 요양보호사의 현장 음성을 사실 단위로 확인한 뒤, 사회복지사가 검토할 수 있는 방문요양 기록지 초안으로 변환하는 양식 자동화 서비스다.**

### 0.2 이번 피벗의 내용

| 구분 | 기존 방향 | 경진대회용 재설계 |
|---|---|---|
| 범위 | 방문요양 행정 전반을 지원하는 AI 에이전트 | 현장 메모를 방문요양 기록지 초안으로 바꾸는 단일 업무 |
| 핵심 사용자 | 방문요양센터 실무자 전반 | 기록을 취합·작성·검토하는 사회복지사 |
| 입력 사용자 | 명확하지 않음 | 현장에서 메모를 남기는 요양보호사 |
| 핵심 가치 | AI 문서 생성과 자동채움 | 부정확한 현장 음성을 확인 가능한 양식으로 변환 |
| 차별화 방식 | RAG·LangGraph·HITL 등 기술 조합 | 음성→사실 확인→양식 초안→사람 승인으로 이어지는 방문요양 전용 흐름 |

### 0.3 프로젝트가 하지 않는 것

- AI가 최종 기록을 승인하거나 외부 시스템에 자동 제출하지 않는다.
- 진단·급여판정·비용산정 등 전문적 판단을 대신하지 않는다.
- 경진대회 단계에서 방문요양 ERP 전체를 대체하지 않는다.
- LangGraph·파인튜닝 등 특정 기술 사용을 목표로 삼지 않는다.

## §1. 문제 정의 — 누가, 언제, 무엇 때문에 힘든가

### 1.1 핵심 페르소나

- **핵심 사용자:** 소형 방문요양센터에서 여러 수급자의 기록을 취합하고 규정 양식으로 작성하는 사회복지사

### 1.2 해결할 단일 문제

### 1.6 왜 치명적인가 — 기록 누락이 부르는 위험 (심사위원용 배경)

> 노인 돌봄에서 "작은 변화를 놓치는 것"은 서류 문제가 아니라 **생명 문제**다. 처음 접하는 사람을 위해 배경부터 짚는다.

**배경 1 — 노인 질환은 '조용하게' 온다 (비전형 발현)**
- 노인 폐렴은 고열·기침 없이 **식욕부진·기력저하·의식저하·낙상**으로만 나타나기도 한다 → 감염을 의심하지 못해 진단이 늦어진다. ([분당서울대병원](https://snubh.org/service/info/com/view.do?BNO=25&Board_ID=B067))
- 그래서 §1.3 장면의 *"점심 거의 안 드심 · 걸을 때 어지럽다"* 는 단순 컨디션이 아니라 **치명 질환의 전조일 수 있다.**

**배경 2 — 그래서 생명은 '미세 변화의 관찰·기록·연결'에 달려 있다**
- 한 번의 관찰이 아니라 식사·기력·피부·정서의 **며칠에 걸친 추세**가 위험 신호다. 흩어진 단편은 신호가 되지 못한다.

**치명 경로 — 초기 신호를 놓치면 어디까지 가나**

| 초기 신호(현장) | 놓치면 | 결과 | 근거 |
|---|---|---|---|
| 식사량·기력 저하 | 흡인성 폐렴 미의심·진단 지연 | 폐농양·패혈증·사망 (폐렴=사망원인 3위, 사망자 90%가 65세+, 80대+ 치사율 ≈50%) | [통계청 인용·의학신문 2023](http://www.bosa.co.kr/news/articleView.html?idxno=2209396) |
| 피부 발적·자세 고정 | 욕창 진행·감염 | 패혈증(전세계 연 약 1천만 명 사망, 욕창이 원인 될 수 있음) | [질병관리청 국가건강정보포털](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=6755) |
| 수분·식사 저하 | 탈수·영양실조 | 섬망·신장애·입원 | 노인의학 일반 `검증 필요` |
| 반응·활동 급변(독거) | 응급 대응 지연(골든타임) | 고독사 (2021년 3,378건, 60세+ 47.5%) | 복지부·보사연 2022 고독사 실태 |

**원인 — 왜 현재의 기록 체계는 이 신호를 놓치는가 (구조적 5지점)**
1. **관찰의 단속성** — 방문은 하루 몇 시간, 나머지 시간은 독거/가족 몫
2. **비전문성** — 요양보호사는 의료인이 아니라 "이게 위험 신호인지" 판단·기록이 어렵다
3. **저해상도 기록** — 주 1회·수기·"특이사항 없음"으로 미세 변화가 뭉개진다
4. **정보 단절** — 교대·현장 메모→사무실 취합 사이에 맥락이 유실된다
5. **취합 지연** — 사회복지사가 모을 땐 이미 시점이 지나 있다

> **결론:** 이 다섯 지점 때문에 조기 신호가 흩어진다. 케어노트AI는 "서류 시간 절감"을 넘어,
> **현장의 미세 신호를 사실로 붙잡아(음성) → 확인·검수 → 사람이 판단(HITL)** 하게 해 이 사슬의 빈틈을 메운다.
> (단, 진단·의료판단은 하지 않는다 — §0.3·§5.5)

> ⚠️ 정직 메모: 위 의학 통계는 2차 출처(병원·언론) 기준 → 발표 전 통계청 원자료·학회지로 재확인.
> "기록 누락이 N명 사망을 유발한다"처럼 **직접 인과로 과장하지 않고**, 개연성·구조적 위험으로 제시한다.

## §3. 솔루션 — 말하면 초안이 되고, 확인된 내용만 기록된다

### 3.1 사용자 흐름

```text
요양보호사
수급자 선택 → 짧게 녹음
        ↓
케어노트AI
음성 전사 → 돌봄 사실 추출 → 불확실한 내용 표시
        ↓
방문요양 기록지 양식에 맞춘 초안 생성
        ↓
사회복지사
원문·경고 확인 → 수정 → 승인
        ↓
승인된 내용만 저장 또는 데모 양식에 자동채움
```

### 3.2 핵심 기능

1. 모바일에서 수급자를 선택하고 짧은 음성을 녹음한다.
2. 음성을 텍스트로 전사하고, 상태 변화·제공 서비스·후속조치 등 사실을 추출한다.
3. 잘 들리지 않거나 확신할 수 없는 표현은 임의로 보완하지 않고 `확인 필요`로 표시한다.
4. 확인된 사실만 방문요양 기록지 필드와 문장 형식으로 변환한다.
5. 사회복지사가 원문과 초안을 비교해 수정·승인한다.
6. 승인값만 저장하거나 허용된 데모 양식에 채운다.

### 3.3 기록지 예시 구성안

발표자료에는 실제 또는 재구성한 비식별 기록지 한 장을 크게 제시한다.

- 왼쪽: 기존 현장 메모
- 가운데: AI가 추출한 사실과 `확인 필요` 항목
- 오른쪽: 방문요양 기록지 초안
- 색상 표시: 원문 근거가 있는 문장 / 사용자가 확인해야 할 문장

## §4. 대표 차별성 — 방문요양 현장을 위한 검증형 양식 자동화

### 4.1 대표 차별성 하나

> 케어노트AI는 음성을 곧바로 그럴듯한 문서로 만드는 도구가 아니라, **현장 음성에서 사실과 불확실성을 분리하고 사람의 확인을 거쳐 방문요양 양식으로 변환하는 서비스**다.

### 4.2 차별성을 만드는 하나의 연결 구조

```text
현장 음성
  → 사실 단위 추출
  → 부정확한 발음·사투리·잡음의 불확실성 표시
  → 부족정보 확인
  → 방문요양 기록지 필드 매핑
  → 사회복지사 승인
```

각 단계는 독립된 차별점이 아니라, **확인되지 않은 내용이 공식 기록으로 넘어가지 않게 하는 하나의 흐름**이다.

### 4.3 혁신성 포지셔닝

- 새로운 AI 모델을 발명하는 프로젝트가 아니다.
- 이미 발전한 음성인식·생성형 AI를 디지털 기술의 혜택이 부족했던 방문요양 기록업무에 적용한다.
- 기술적 새로움보다 **도메인 특화 과정과 안전한 업무 연결**을 혁신성으로 제시한다.
- “범용 AI를 호출한다”가 아니라 “방문요양 현장의 입력·확인·양식·책임 구조에 맞춘다”고 설명한다.

## §5. 실현 방법 — 기술은 목적이 아니라 흐름을 구현하는 수단

### 5.1 최소 시스템 구조

```text
[모바일 웹 또는 앱]
수급자 선택·녹음·업로드
        ↓
[API 서버]
사용자·권한·녹음 작업 관리
        ↓
[음성 처리]
STT 전사·신뢰도·불확실 구간 검출
        ↓
[기록 생성]
사실 추출·양식 매핑·초안 생성·규칙 검증
        ↓
[검토 웹]
원문 비교·수정·승인·감사기록
```

### 5.2 앱과 웹의 역할

| 영역 | 역할 | 설계 원칙 |
|---|---|---|
| 모바일 앱/웹 | 현장 녹음, 수급자 선택, 처리상태 확인 | 버튼과 입력을 최소화 |
| 서버 | 인증, 저장, 처리 요청, 승인상태 관리 | 조직·사용자별 데이터 분리 |
| AI 처리부 | 전사, 사실 추출, 양식 초안 | 구조화된 출력과 근거 연결 |
| 검토 웹 | 사회복지사의 비교·수정·승인 | 최종 책임과 판단을 사람에게 유지 |

`검증 필요`: 경진대회 PoC는 설치 부담이 낮은 모바일 반응형 웹을 우선 검토하고, 네이티브 앱은 오프라인·백그라운드 녹음 필요성이 확인될 때 선택한다.

### 5.3 에이전트 적용 원칙

- 단순한 `음성→전사→초안`은 일반 API 파이프라인으로 구현할 수 있다.
- 부족정보 질문, 재입력, 승인 대기, 검증 실패 재처리처럼 상태 전이가 필요한 경우에만 에이전트 또는 워크플로 엔진을 사용한다.
- LangGraph는 필수가 아니며, 속도·복잡도·상태관리 이점을 비교한 후 선택한다.
- 발표에서는 프레임워크 이름보다 사용자의 처리 흐름을 설명한다.

### 5.4 파인튜닝 적용 원칙

- 초기 MVP는 프롬프트, 구조화 출력, 돌봄 용어사전, 양식 규칙으로 기준 성능을 만든다.
- 비식별 학습 데이터가 충분히 확보된 뒤 기본 모델과 파인튜닝 모델을 비교한다.
- 정확도 또는 일관성 개선이 검증될 때만 적용한다.
- 파인튜닝 자체를 차별점이나 완성도 증거로 사용하지 않는다.

### 5.5 안전 원칙

- AI는 초안을 생성하지만 승인·제출하지 않는다.
- STT 신뢰도가 낮은 구간은 추측하지 않고 사용자 확인을 요청한다.
- 외부 AI 전송 전 개인정보를 마스킹한다.
- 원문, 생성, 수정, 승인 이력을 감사로그로 남긴다.
- 자동채움은 데모 또는 허용된 자체 양식에서만 검증한다.

## §7. 검증 방법 — ‘된다’가 아니라 어떻게 확인할지 제시한다

### 7.1 핵심 검증 질문

1. 사회복지사의 기록 작성시간이 실제로 줄어드는가?
2. 부정확한 발음·사투리·잡음에서도 핵심 돌봄 사실을 보존하는가?
3. AI가 원문에 없는 사실을 추가하거나 중요한 사실을 누락하지 않는가?
4. 사용자가 초안을 수정하는 시간이 직접 작성하는 시간보다 짧은가?
5. 실제 방문요양 기록지의 필드와 표현에 맞는 결과를 만드는가?

### 7.2 평가 설계

| 검증 대상 | 비교 방법 | 지표 | 성공 기준 |
|---|---|---|---|
| 작성 효율 | 동일 사례 수기 작성 vs AI 초안 수정 | 총 작성시간, 수정시간 | `파일럿 전 확정` |
| 음성인식 | 표준어·사투리·소음 음성 평가 | CER/WER, 핵심어 인식률 | `벤치마크 후 확정` |
| 사실 정확성 | 원음·전사문과 초안 대조 | 사실 정확도, 누락률, 환각률 | `평가셋 구축 후 확정` |
| 양식 적합성 | 전문가 체크리스트 평가 | 필수 필드 충족률, 표현 적절성 | `양식 확정 후 설정` |
| 안전성 | 의도적으로 오류를 넣은 테스트 | 경고 탐지율, 승인 차단률 | 중요 오류 100% 탐지 목표 |
| 사용성 | 사회복지사·요양보호사 과업 테스트 | SUS 또는 5점 척도, 인터뷰 | `참여자 확보 후 확정` |

### 7.3 통계자료 배치 원칙

- 도입부에는 문제의 크기를 설명하는 공식 통계 1~2개만 사용한다.
- 기술 성능 통계는 솔루션 소개 이후 검증 슬라이드에 배치한다.
- 선행연구 결과, 공식 통계, 자체 목표치를 시각적으로 구분한다.
- 자체 측정 전에는 기대치를 실제 성과처럼 표현하지 않는다.

| 12 | 어떻게 구현하고 확장할 것인가? | 로드맵·팀 |
| 13 | 마지막 한 문장은 무엇인가? | 핵심 메시지 반복 |

### 12.1 슬라이드 분량 배분 (40장 예산 · 15분)

> 40장은 **상한**이다. 말로 끌고 가는 핵심 슬라이드 ~28장 + 부록 4~6장, 나머지는 빌드·전환.
> 배점 60점 구간(문제·차별성·기대효과)에 슬라이드·시간의 절반 이상을 배분한다.

| 섹션 | 슬라이드 | 시간 | 노리는 배점 |
|---|---:|---:|---|
| 0. 표지·팀(한 줄) | 1 | 20s | — |
| 1. 문제·배경 ⭐ | 6~7 | 3.5분 | 혁신성·기대효과 토대 |
| 2. 솔루션(흐름·기록지 예시) | 5~6 | 3분 | 혁신성 |
| 3. 차별성 ⭐ | 3~4 | 2분 | **혁신성 30** |
| 4. 실행·기술·안전·검증 **(+로드맵 1장 흡수)** | 6~7 | 3분 | **실행 20 + 계획 10** |
| 5. 기대효과 ⭐ | 3~4 | 2분 | **기대효과 30** |
| 7. 마무리(핵심 메시지) | 1~2 | 1분 | 프레젠테이션 |
| 부록(Q&A 대비, 발표 X) | 4~6 | — | 출처·상세데이터·기술상세 |

> 계획·팀 10점은 독립 섹션 없이 흡수: **로드맵 → §4에 1장**, **팀 → 표지/마무리 한 줄**.
> 도입부 통계는 딱 2개(폐렴 3위·무증상 흡인 55%)만 크게, 나머지는 뒤·부록으로.

### PPT 작성 원칙

- 한 슬라이드에 주장 하나만 둔다.
- 제목은 항목명이 아니라 결론형 문장으로 쓴다.
- 본문 설명보다 실제 기록지·사용자 흐름·전후 비교를 크게 보여준다.
- 출처는 발표 화면에서 읽을 수 있는 크기로 표시한다.
- 기술 용어는 필요한 경우에만 사용하고, 먼저 사용자 가치를 설명한다.
- 심사위원이 의문을 가질 숫자는 출처·산식·측정 여부를 함께 표시한다.

**검사 논고: 이 설계는 서술된 그대로는 8주 안에 수상 가능한 구현이 되지 않는다.**

1. **범위가 8주·인원 미상에 비해 과하다.**
증거: 8주 계획에 에이전트 6종, 상태기계, 검토 UI, 음성 업로드, 자가개선 하네스(B), 온디바이스 STT(C), 골든셋 60건, 5행 ablation이 모두 들어 있다. 팀 규모는 "확인되지 않았다", 열린 결정 5번은 "팀 구성·역할 (대회 공고 확인 후)"이다. 인력도 모르면서 일정을 확정했다.
비용: 4주차 게이트가 밀리면 B·C·UI가 연쇄로 무너져 "설계 + 부분 시연"만 남는다. 구현 경진대회에서 이것은 사실상 탈락이다.

2. **"최소 수상 라인"은 근거 없는 가정이다.**
증거: "ablation 표 4행 — 최소 수상 라인". 그런데 "공고(평가기준, 제출 형태, 배점)는 아직 공개되지 않았다". 평가 기준을 모르면서 어느 선이 수상선인지 정할 수 없다. 리스크표도 "배점이 나오면 3·8장 재조정"이라 인정한다.
비용: 4주 치 핵심 노력이 심사가 보지 않는 축(ablation 수치)에 쏠릴 수 있다. 라이브 시연이나 사용성 배점이 크면 UI가 5주차에야 시작되는 일정은 치명적이다.

3. **혁신 축의 동기가 대회가 아니라 사용자의 불안이다.**
증거: "기존 설계가 '기술적으로 혁신이 부족하다'고 느껴 최신 기술(멀티에이전트 등)을 넣고 싶어 한다." 원칙 5는 "혁신은 수치로 증명되는 것만"이라 하면서, 같은 문서의 ablation 표는 전부 빈칸이고 멀티에이전트가 단일 LLM보다 낫다는 증거가 없다.
비용: 단순한 구조가 더 나은 것으로 측정되면 발표의 뼈대가 무너진다. 가설이 틀려도 8주 중 4주를 이미 썼다.

4. **이미 수상한 것은 아이디어이고, 구현 단계의 검증 대상이 되는 핵심 위험이 뒤로 밀려 있다.**
증거: 온디바이스 한국어 STT 정확도는 7주차 PoC이고, 위험표는 "C 약화"라는 영향만 적고 있다. 프로젝트 문서는 "음성은 STT 전에 마스킹 불가"라고 적었는데, 청사진은 C를 핵심 혁신으로 내세운다. Re-listener도 "오디오 모델 API 변동"에 의존하며 모델은 아직 미정이다(열린 결정 2).
비용: 가장 불확실한 두 축(C, Re-listener)이 후반 또는 모델 미확정 상태에 있어, 늦게 실패가 드러나면 만회할 시간이 없다.

5. **데이터가 전부 합성이다.**
증거: "합성 transcript 60건", "합성 음성(TTS)". 기록은 방언·말더듬·현장 소음이 핵심인데 TTS 중심이다.
비용: "근거 없는 값 0%" 같은 수치가 자체 합성 데이터 위의 자기 채점이 되어, 심사위원이 일반화 가능성을 의심하면 증명력이 약해진다.
